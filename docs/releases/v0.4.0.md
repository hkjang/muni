AI 기능의 문제 두 건을 고치고, 버전 복원이 실제로 적용되도록 바로잡았습니다. AI 호출 감사 화면과 발표자료 연동 설정 화면이 새로 들어갔습니다.

## 수정

### 버전을 복원해도 이전 내용이 되돌아오던 문제

버전 기록에서 복원을 눌러도 잠시 후 예전 내용이 그대로 남아 있었습니다.

편집기는 저장된 본문이 아니라 **CRDT**로 동작하고, 브라우저는 그 사본을 IndexedDB에 따로 보관합니다. 서버는 복원된 본문을 저장하고 공동편집 기록을 비웠지만, 화면이 새로 열리면 브라우저가 **복원 이전 문서를 그대로 재생**한 뒤 "서버에 없는 내용"이라며 다시 올려보냈습니다. 문서를 열어 두고 있던 다른 사람도 똑같이 했습니다.

문서에는 공유 상태가 통째로 교체될 때 올라가는 세대 번호가 이미 있었습니다. 이제 이 번호가 **브라우저 사본의 이름에 포함**됩니다.

- 복원된 문서는 새 사본으로 열리고, 이전 사본은 병합되지 않고 삭제됩니다.
- 이미 연결돼 있던 편집기는 다시 연결하도록 안내됩니다.
- 페이지를 연 뒤에 복원이 일어났다면, 로컬 내용을 올려보내지 않고 새로 고칩니다.

빈 문서를 채우는 일도 한 명에게만 맡깁니다. 새 문서와 방금 복원된 문서는 클라이언트 입장에서 똑같이 비어 있어서, 두 브라우저가 동시에 저장된 본문을 써 넣으면 **본문이 두 번** 들어갔습니다.

### AI로 다듬으면 서식이 사라지던 문제

선택한 문장을 AI로 다듬으면 굵게, 링크, 목록 구조, 제목 단계가 모두 사라진 채 반영됐습니다.

선택 영역을 **평문으로** 모델에 넘기고 있었기 때문입니다. 서식이 모델에 도달한 적이 없으니 답변에 들어 있을 수도 없었고, 그 평문이 서식 있던 원문을 대체했습니다.

이제 선택 영역을 Markdown으로 써서 보내고, 표시를 유지하도록 요청하며, 답변을 다시 Markdown으로 읽어 실제 서식으로 반영합니다.

- 문장 안에서 끝나는 수정은 여전히 문단이 아니라 **그 단어들만** 교체합니다.
- 제목을 다듬으면 제목으로 남습니다.
- 목록, 표, 인용, 코드 블록, 링크, 굵게·기울임·취소선을 읽고 씁니다.

## 추가

### AI 호출 감사

`서비스 관리 → AI 호출 감사`에서 누가 어떤 문서에서 AI를 사용했는지 확인할 수 있습니다.

기록하는 항목은 사용자, 기능, 문서, 모델, 모델이 보고한 토큰 사용량, 소요 시간, 성공 여부입니다. 기간과 결과로 걸러 볼 수 있고, 기능별 호출 수와 토큰 합계를 함께 보여줍니다.

**주고받은 내용은 저장하지 않고 분량만 남깁니다.** 문서는 사람들이 AI 사용을 망설이는 이유이고, 비용에 대한 질문에는 분량이면 충분합니다.

기존에도 표는 있었지만 아무것도 기록되지 않아 어떤 질문에도 답할 수 없었습니다.

### 발표자료(Ptium) 연동 설정

`서비스 관리 → 발표자료 연동`이 생겼습니다. API 주소, 편집 화면 주소, API key, 기본 테마와 언어, timeout을 입력하고 연결을 시험할 수 있습니다.

서버는 연동이 들어올 때부터 이 설정을 지원했지만 입력할 화면이 없어 데이터베이스에 직접 써 넣어야 했고, 다른 탭을 저장하면 브라우저가 Ptium 항목이 빠진 설정을 보내 **값이 지워졌습니다**.

### 관리자 진입 경로

관리자가 서비스 관리로 가려면 우측 상단 아바타 메뉴를 알고 있어야 했습니다. 이제 왼쪽 사이드바에 **서비스 관리** 항목이 있고, 빠른 이동(`Ctrl+K`)에서도 관리 화면을 찾을 수 있습니다. 관리자가 아닌 사용자에게는 어느 쪽에도 보이지 않습니다.

## 개선

### 문서 Agent가 작업하는 동안 화면이 멈춰 있던 문제

워크스페이스 문서까지 찾아보는 Agent는 도구 호출을 모두 끝낸 뒤에야 결과를 한 번에 보냈습니다. 세 번 찾아봐야 하는 질문은 그동안 멈춘 것처럼 보였습니다.

이제 각 단계를 도착하는 대로 읽습니다. 답변은 쓰이는 대로 화면에 나타나고, 어떤 문서를 찾아보는 중인지도 그 시점에 표시됩니다. 스트리밍을 지원하지 않는 게이트웨이는 이전처럼 한 번에 답합니다.

스트리밍 중에 발생한 오류도 화면에 표시됩니다. 응답이 이미 시작된 뒤라 상태 코드로는 전달할 수 없어, 그동안 아무 일도 일어나지 않은 것처럼 보였습니다.

### 답변을 Markdown으로 표시

AI 답변은 요청하지 않아도 Markdown으로 돌아옵니다. 그대로 보여주니 `###`과 `**`이 뒤섞여 읽기 어려웠습니다. 이제 제목, 목록, 표, 인용, 코드 블록을 그대로 렌더링합니다. **커서 위치에 삽입**도 서식을 유지한 채 들어갑니다.

모델의 출력을 HTML로 해석하는 경로는 없습니다. 화면에 그리는 트리는 원본 텍스트에서 직접 만듭니다.

### 추론 영역 접기

추론은 도착하는 대로 별도 영역에 표시되고, 답변이 시작되면 접힙니다. 나중에 다시 펼 수 있습니다.

## 업그레이드

데이터베이스 마이그레이션이 하나 추가됩니다(`005_ai_invocation_audit.sql`). 서버가 시작할 때 자동으로 적용되며, 기존 표에 열과 인덱스를 추가할 뿐 기존 데이터를 바꾸지 않습니다.

```bash
gzip -dc muni-v0.4.0.tar.gz | docker load
docker compose -f compose.example.yaml --env-file .env up -d
```

복원 수정은 브라우저에 남아 있는 기존 사본과 무관하게 동작합니다. 업그레이드 후 첫 접속에서 이름이 달라진 사본을 새로 만들고, 예전 사본은 정리합니다.

## 오프라인 설치

릴리스 asset에는 `muni:v0.4.0` Docker 이미지가 포함되어 있습니다.

```bash
gzip -dc muni-v0.4.0.tar.gz | docker load
docker image inspect muni:v0.4.0

cp .env.example .env
# .env의 네 값을 운영 환경에 맞게 변경합니다.
docker compose -f compose.example.yaml --env-file .env up -d
```

애플리케이션이 반드시 필요로 하는 런타임 환경변수는 다음 네 개입니다.

| 환경변수                   | 설명                                 |
| -------------------------- | ------------------------------------ |
| `POSTGRES_DSN`             | PostgreSQL 접속 문자열               |
| `BOOTSTRAP_ADMIN`          | 최초 관리자 아이디 또는 이메일       |
| `BOOTSTRAP_ADMIN_PASSWORD` | 최초 관리자 비밀번호(12자 이상)      |
| `ENCRYPTION_KEY`           | base64로 인코딩한 32-byte master key |

PDF 변환 동작만 조정하는 선택 환경변수가 두 개 있습니다.

| 환경변수               | 기본값    | 설명                                       |
| ---------------------- | --------- | ------------------------------------------ |
| `MUNI_CHROMIUM_PATH`   | 자동 탐색 | PDF Export에 사용할 headless 브라우저 경로 |
| `MUNI_PDF_CONCURRENCY` | `2`       | 동시에 실행할 Chromium 프로세스 수(1~32)   |
