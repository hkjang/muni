워드에서 가져온 문서가 muni에서 어떻게 보이는지에 관한 릴리스입니다. 그림이 들어 있는 워드 문서는 아예 열리지 않고 있었고, 열린 문서들도 서식의 상당 부분을 두고 왔습니다 — **스타일로 준 서식은 전부**.

## 수정

### 그림이 있는 워드 문서가 열리지 않았습니다

워드는 그림을 그것이 놓인 문장 **안에** 씁니다. Markdown도 HTML도 그렇습니다. muni의 편집기는 그림을 자기 줄을 가진 블록으로 그립니다.

이 둘은 어긋나기만 하는 것이 아닙니다. ProseMirror는 담을 수 없는 모양을 만나면 **그림만 잃는 것이 아니라 문서 전체를 거부합니다.** 사진이 한 장이라도 들어 있는 `.docx`는 가져온 뒤 열리지 않았습니다.

가져오기가 그 모양을 바꿉니다 — 그림 앞의 말, 그림, 그림 뒤의 말. 문단의 서식은 나뉜 양쪽 모두에 따라가고, 목록 항목은 자기 내용 모형이 요구하는 대로 문단으로 시작합니다.

**이미 저장되어 있는 문서는 읽는 순간 고쳐집니다.** 편집기와 공개 링크 양쪽 모두입니다. 데이터베이스의 내용은 다음 저장 때 새 모양으로 바뀝니다.

### 스타일로 준 서식을 전부 잃고 있었습니다

세 가지가 같은 뿌리였습니다. **워드 문서의 서식은 대개 그것이 붙은 자리에 적혀 있지 않고, 스타일에 적혀 있습니다.** muni는 붙은 자리만 읽고 있었습니다.

| 워드가 적는 곳 | muni가 잃던 것 |
| --- | --- |
| 문자 스타일 (`Strong`, `Emphasis`, 기관 서식) | **굵게·기울임·색 전부.** Ctrl+B로 직접 준 것만 살아남았습니다 |
| 문단 스타일 (`본문` 같은 것) | **들여쓰기·줄간격·정렬 전부.** 모든 문단이 왼쪽 끝에 한 줄 간격으로 |
| 표 스타일 | **머리글 행.** 굵기도 음영도 없는 보통 행이 되었습니다 |

서식 갤러리로 준 서식, 즉 **템플릿이 서식을 주는 방식 그대로 만든 문서가 맨 글자로 들어오고 있었습니다.**

이제 각각의 스타일이 정한 것을 `basedOn` 사슬을 따라 읽고, 그 위에 문단이나 런이 스스로 정한 것을 얹습니다. **직접 준 쪽이 이깁니다** — 굵기를 끈 사람은 끈 것을 의도한 것이고, 한 줄만 가운데로 놓은 사람은 그 한 줄을 의도한 것입니다.

표 머리글은 조금 다릅니다. 워드는 머리글 행을 행에 적지 않습니다. `w:tblHeader`는 "쪽마다 이 행을 반복하라"는 인쇄 지시라 대부분의 표에는 없고, 머리글은 사실 `w:tblLook`이 켜는 표 스타일의 첫 행 서식입니다. 그런데 **`w:tblLook`은 거의 모든 표에 붙어 있습니다 — 모든 행을 똑같이 그리는 Table Grid에도.** 그것만 믿으면 문서에 없던 머리글을 지어냅니다. 그래서 스타일에게 첫 행을 다르게 그리는지도 함께 묻습니다.

### 목차가 굳은 채로 들어왔습니다

워드는 목차를 **마지막으로 계산한 항목들을 감싼 필드**로 씁니다. 워드는 그것을 필요할 때 다시 만들지만, muni는 그 캐시를 그냥 글로 읽었습니다. 결과는 다시는 맞을 수 없는 쪽 번호 목록이었고 — muni에는 인쇄하기 전까지 쪽이 없습니다 — muni가 가진 살아있는 목차 노드는 만들어지지 않았습니다.

이제 그 필드가 목차 노드가 되고 캐시는 버려집니다. 다른 필드는 그대로입니다. 문장 한가운데의 `PAGEREF`는 그 문장을 데려가지 않습니다.

## 추가

### 워드로 내보낸 문서에도 쪽 번호가 있습니다

muni의 PDF 내보내기는 처음부터 바닥글에 쪽 번호를 넣었습니다. `.docx` 내보내기는 바닥글을 맨 글자로 썼습니다. **같은 문서를 인쇄하면 쪽 번호가 있고 워드로 열면 없었습니다.**

이제 워드 자신의 `PAGE`와 `NUMPAGES` 필드가 들어갑니다. 자리도 PDF와 같습니다 — 글은 왼쪽, 번호는 오른쪽 여백에. 바닥글에 쓸 말이 없어도 들어갑니다. **쪽 번호는 문서의 것이 아니라 쪽의 것이기 때문입니다.**

파일을 다시 읽을 때는 첫 필드에서 멈춥니다. muni는 머리글과 바닥글을 각각 문자열 하나로 들고 있어서 계수기를 둘 자리가 없고, 번호를 글로 읽으면 `내부 열람용`이 `내부 열람용1 / 1`이 됩니다 — 왕복할 때마다 조금씩 길어지는 종류의 잘못입니다.

## 다시 생기지 않도록

이 릴리스의 워드 관련 문제 네 가지는 **모두 같은 이유로 기존 테스트에 보이지 않았습니다.** 가져오기 테스트가 전부 muni가 쓴 파일을 muni가 읽는 왕복이었습니다. 그런 테스트는 muni가 자기 자신과 어긋나는 것만 찾을 수 있습니다 — 스타일을 가리키는 런도, 목차 필드도, 스타일이 그리는 머리글 행도 muni의 쓰기가 만들지 않는 모양입니다.

테스트에 `wordPackage`가 생겼습니다. **muni가 결코 쓰지 않을 본문을 감싼 `.docx`를 만듭니다.** 위의 네 가지는 전부 그것으로 찾았고, 확인은 python-docx가 쓴 진짜 워드 파일로 했습니다.

편집기 쪽에도 하나 늘었습니다. 서버가 만들 수 있는 mark와 노드를 대조하던 기존 검사는 **낱말**을 봅니다. 이번 그림 문제는 아는 노드와 아는 속성만 써서 모든 내보내기 형식을 통과하고도 열리지 않았습니다 — 문제는 **모양**이었습니다. 이제 서버의 커버리지 문서를 편집기에 그대로 넣어보는 검사가 있습니다. 그 문서는 파일 하나이고 Go 테스트 두 개와 편집기 테스트가 함께 읽습니다. 사본은 어긋나고, 어긋난 사본은 아무것도 찾지 못합니다.

## 업그레이드

마이그레이션과 설정 변경은 필요하지 않습니다.

```bash
gzip -dc muni-v0.17.0.tar.gz | docker load
docker compose -f compose.example.yaml --env-file .env up -d
```

**이미 들어와 있는 문서 중 그림 때문에 열리지 않던 것은 이 버전에서 열립니다** — 읽는 순간 고쳐지므로 다시 가져올 필요가 없습니다. 스타일로 준 서식을 잃은 문서는 그 손실이 가져오던 시점에 일어났으므로 되돌아오지 않습니다. **원본 워드 파일이 남아 있다면 다시 가져오면 이번에는 그대로 들어옵니다.**

## 오프라인 설치

릴리스 asset에는 `muni:v0.17.0` Docker 이미지가 포함되어 있습니다.

```bash
gzip -dc muni-v0.17.0.tar.gz | docker load
docker image inspect muni:v0.17.0

cp .env.example .env
# .env의 네 값을 운영 환경에 맞게 변경합니다.
docker compose -f compose.example.yaml --env-file .env up -d
```

애플리케이션이 반드시 필요로 하는 런타임 환경변수는 다음 네 개입니다.

| 환경변수                   | 설명                                 |
| -------------------------- | ------------------------------------ |
| `POSTGRES_DSN`             | PostgreSQL 접속 문자열               |
| `BOOTSTRAP_ADMIN`          | 최초 관리자 아이디 또는 이메일       |
| `BOOTSTRAP_ADMIN_PASSWORD` | 최초 관리자 비밀번호(12자 이상)      |
| `ENCRYPTION_KEY`           | base64로 인코딩한 32-byte master key |

PDF 변환 동작만 조정하는 선택 환경변수가 두 개 있습니다.

| 환경변수               | 기본값    | 설명                                       |
| ---------------------- | --------- | ------------------------------------------ |
| `MUNI_CHROMIUM_PATH`   | 자동 탐색 | PDF Export에 사용할 headless 브라우저 경로 |
| `MUNI_PDF_CONCURRENCY` | `2`       | 동시에 실행할 Chromium 프로세스 수(1~32)   |

## 운영 정보

- 서비스 포트: `8080`
- Liveness: `/healthz`
- Readiness: `/readyz`
- REST API: `/api/v1`
- 공개 링크: `/s/{token}` — 인증 없이 열리는 유일한 화면입니다
- OpenAPI: `/api/openapi.yaml` — 실제 라우트와 일치하며, 테스트가 그것을 지킵니다
- Prometheus: `/metrics` — 관리자 인증 필요
- MCP: `/mcp`
- 지원 DB: PostgreSQL 15 이상
- 이미지에는 PDF Export용 Chromium과 Noto CJK 글꼴이 포함되어 있습니다.
