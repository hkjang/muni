편집 화면 고도화 두 번째 릴리스입니다. 구글 독스를 쓰던 사람이 찾다가 없어서 아쉬웠던 기능을 계속 채웠고, 그 과정에서 발견한 내보내기 누락을 함께 고쳤습니다.

## 수정

### 서식이 내보내기에 반영되지 않던 문제

v0.4.0과 v0.5.0에서 추가한 **줄 간격, 문단 들여쓰기, 첫 줄 들여쓰기가 어떤 내보내기에도 반영되지 않았습니다.**

문서에는 저장되는데 HTML·PDF·DOCX 작성기가 통째로 버리고 있었습니다. 보고서 양식대로 줄 간격 160%에 들여쓰기를 넣어 작성한 문서가, 내보내면 평평하게 나왔습니다. 내보내기가 그 기능들의 존재 이유였는데도요.

세 가지 모두 이제 내보냅니다. 표 안에서는 작성자가 지정한 줄 간격과 표 기본값을 **하나로 합칩니다** — `CT_PPr`은 `w:spacing`을 하나만 허용하고, 둘이면 Word가 파일 자체를 거부합니다.

python-docx로 독립 검증했습니다. 줄 간격 1.5·1.6·2.0, 들여쓰기 0.61in, 첫 줄 0.15in, 양쪽 정렬이 모두 쓴 대로 읽힙니다.

### 이미지 정렬이 내보내기에서 사라지던 문제

이미지는 내보내기에서 자체 블록이라 태그 자체에 정렬할 대상이 없었습니다. 가운데·오른쪽 정렬이 버려지고 있어, 정렬을 담는 요소로 감싸도록 고쳤습니다.

## 추가

### 삽입 메뉴

단어가 시작하는 자리에서 `/`를 누르면 목록이 열립니다. 제목 1~3, 본문, 글머리 기호, 번호 매기기, 체크리스트, 인용, 코드 블록, 표, 이미지, 가로 구분선, 페이지 나누기, 목차, 오늘 날짜.

도구 모음까지 가려면 키보드를 떠나야 하고, 애초에 도구 모음이 전부를 담을 수도 없습니다.

트리거는 **단어가 시작하는 자리**여야 합니다. `2026/08`처럼 쓴 날짜나 문장 속 경로에서는 열리지 않습니다.

### 페이지 나누기

`Ctrl+Enter`. 끝까지 갑니다.

- 쓰는 동안에는 표시선으로 보입니다. 표시가 없으면 세 쪽으로 인쇄될 문서와 한 쪽으로 인쇄될 문서를 구분할 방법이 없습니다.
- 인쇄하면 실제로 쪽이 나뉩니다.
- DOCX로는 `<w:br w:type="page"/>`로 나갑니다.
- 그 파일을 다시 가져오면 그대로 복원됩니다. Word가 이 표시를 문단 속성과 문단 안의 run 두 가지로 쓰는데, 둘 다 읽습니다.

### 문단 들여쓰기와 양쪽 정렬

`Tab`으로 문단을 들이고 `Shift+Tab`으로 뺍니다. 첫 줄만 들여쓸 수도 있습니다. 목록 안에서는 `Tab`이 원래대로 한 단계 안으로 들어갑니다.

한국어 문서가 늘 요구하는 서식인데, 그동안은 앞 공백(내보내면 사라짐)이나 불릿을 숨긴 목록으로 흉내 내야 했습니다. 들여쓰기는 길이가 아니라 **단계 수**로 저장하므로, 배율을 바꾸거나 인쇄해도 의미가 달라지지 않습니다.

정렬 그룹에는 **양쪽 정렬**이 빠져 있었습니다. 보고서 양식이 가장 많이 요구하는 정렬입니다.

### 문서 안 목차

`/목차`로 넣습니다. 문서를 여는 차례 페이지이고, 손으로 맞춰 두기 가장 싫은 부분이기도 합니다.

노드 안에는 아무것도 저장하지 않습니다. 그릴 때마다, 그리고 내보낼 때 다시 제목에서 계산하므로 **목차가 본문과 어긋날 수 없습니다.**

HTML·PDF·DOCX·Markdown·텍스트 모두에 들어가며, 왼쪽 개요 패널과 같은 방식으로 들여씁니다. 제목이 하나도 없으면 빈칸 대신 그렇다고 적습니다.

### 이미지 크기와 정렬

이미지를 선택하면 25·50·75·100%, 왼쪽·가운데·오른쪽, 그리고 화면 낭독기가 읽을 설명을 지정할 수 있습니다.

그동안 이미지는 원본 크기 그대로 왼쪽에 들어가 그 자리에 머물렀습니다. 스크린샷 하나가 전체 폭을 차지한 채로요. 지면을 구성할 방법이 없었습니다.

### 링크 편집

링크를 누르면 아래에 작은 바가 열립니다. 주소, 열기, 변경, 제거.

그동안은 `window.prompt`로 편집했습니다. 지금 어디를 가리키는지 보여주려면 입력창에 미리 채워 넣는 수밖에 없고, 그러면 읽는 사람이 한 글자씩 뜯어봐야 합니다.

주소는 쓰는 대로 받습니다. `example.com`은 https로, 이메일 형태는 mailto로 처리합니다. **코드를 실행시키는 스킴은 거부합니다** — 여러 사람이 여는 문서에 들어가면 그건 문서를 여는 사람에 대한 공격입니다.

### 댓글 스레드

답글이 답한 댓글 아래에 붙습니다. 해결은 스레드 단위로 동작하고, 해결된 스레드는 다시 열 수 있으며, 열린 스레드가 위로 옵니다.

서버는 처음부터 부모 댓글을 저장하고 있었는데 패널이 전부 평면으로 나열해서, 답글이 한참 아래에 무관한 말처럼 떠 있었습니다.

### 마지막 편집 위치

긴 문서를 다시 열면 커서가 있던 자리로 돌아갑니다. 스크롤할 만큼 긴 문서에서만, 그리고 그 위치가 아직 존재할 때만 동작합니다. 브라우저에만 저장되며 문서와 함께 나가지 않습니다.

## 업그레이드

데이터베이스 마이그레이션과 설정 변경은 필요하지 않습니다. 새 이미지로 교체하면 됩니다.

```bash
gzip -dc muni-v0.6.0.tar.gz | docker load
docker compose -f compose.example.yaml --env-file .env up -d
```

기존 문서는 그대로 열립니다. 이번에 추가된 서식은 지정한 문서에만 적용됩니다.

## 오프라인 설치

릴리스 asset에는 `muni:v0.6.0` Docker 이미지가 포함되어 있습니다.

```bash
gzip -dc muni-v0.6.0.tar.gz | docker load
docker image inspect muni:v0.6.0

cp .env.example .env
# .env의 네 값을 운영 환경에 맞게 변경합니다.
docker compose -f compose.example.yaml --env-file .env up -d
```

애플리케이션이 반드시 필요로 하는 런타임 환경변수는 다음 네 개입니다.

| 환경변수                   | 설명                                 |
| -------------------------- | ------------------------------------ |
| `POSTGRES_DSN`             | PostgreSQL 접속 문자열               |
| `BOOTSTRAP_ADMIN`          | 최초 관리자 아이디 또는 이메일       |
| `BOOTSTRAP_ADMIN_PASSWORD` | 최초 관리자 비밀번호(12자 이상)      |
| `ENCRYPTION_KEY`           | base64로 인코딩한 32-byte master key |

PDF 변환 동작만 조정하는 선택 환경변수가 두 개 있습니다.

| 환경변수               | 기본값    | 설명                                       |
| ---------------------- | --------- | ------------------------------------------ |
| `MUNI_CHROMIUM_PATH`   | 자동 탐색 | PDF Export에 사용할 headless 브라우저 경로 |
| `MUNI_PDF_CONCURRENCY` | `2`       | 동시에 실행할 Chromium 프로세스 수(1~32)   |
