워드 문서에 위첨자가 하나라도 있으면 그 문단이 통째로 사라지고 있었습니다. 그리고 각주가 생겼습니다 — 워드에 있고 muni에 없던 마지막 기능입니다.

## 수정

### 위첨자 하나가 문단을 지우고 있었습니다

muni의 백엔드는 위첨자와 아래첨자를 완전히 지원합니다. `.docx`에서 읽고, `w:vertAlign`으로 쓰고, HTML로도 그립니다. **편집기 스키마에만 없었습니다.**

ProseMirror는 모르는 mark를 무시하지 않습니다. **그 mark가 붙은 문단의 내용을 통째로 버립니다** — 서식만이 아니라 글자까지. 대조 실험으로 확인했습니다.

| 문단에 넣은 것 | 열었을 때 남은 것 |
| --- | --- |
| `bold` (편집기가 아는 mark) | `면적 3m` + 굵은 `2` |
| `superscript` (모르는 mark) | **아무것도 없는 빈 문단** |
| mark 없음 | `면적 3m2` |

아무 서식도 없던 "면적 3m"까지 사라집니다. 즉 **m²·H₂O·각주 번호·수식의 지수가 들어 있는 워드 문서를 muni에서 열면 그 글자가 있던 문단이 사라진 채 열렸고, 다음 자동 저장이 그 손실을 확정했습니다.**

확장 두 개를 편집기와 공개 링크 화면 양쪽에 넣고 툴바에 버튼을 붙였습니다. 지금까지 읽을 수는 있어도 만들 수는 없던 서식입니다.

### 목차가 있는 문서를 링크로 공유하면 목차가 없었습니다

같은 뿌리입니다. 편집기와 공개 링크 화면이 확장 목록을 각자 손으로 적고 있었고, 공개 화면에만 목차 노드가 빠져 있었습니다. 모르는 노드는 자기 내용을 데리고 사라집니다.

`documentExtensions()` 하나로 합쳤습니다. 연결이 필요하거나 편집에만 쓰이는 것(협업, 플레이스홀더, 붙여넣기 처리, 검색 강조)은 그것을 필요로 하는 화면이 얹습니다 — 스키마를 바꾸지 않는 것들입니다.

### 다시 생기지 않도록

서버가 만들 수 있는 mark와 노드의 목록을 편집기 스키마와 대조하는 검사를 남겼습니다. 목록은 Go 쪽에서 가져오지 않고 손으로 적었습니다 — 두 쪽이 다른 언어로 쓰여 있고, 이 검사의 목적이 바로 **둘이 어긋나는 순간을 알아채는 것**이기 때문입니다. 스키마는 두 화면이 함께 쓰는 그 목록에서 직접 만듭니다. 사본을 검사하면 사본이 자기 자신과 일치한다는 것만 증명되는데, 애초에 공개 화면이 목차를 잃은 경위가 그것이었습니다.

검사가 실제로 잡는지 확인했습니다. 확장을 하나씩 빼고 돌려서 빠진 이름을 짚는지, 문단이 사라진다는 것을 따로 짚는지 봤습니다.

## 추가

### 각주

보고서에 흔한데 muni에는 아예 없었습니다.

주석의 글자는 노드 안에, 문장에서 그것이 붙는 자리에 삽니다. 문장을 옮기면 주석이 따라옵니다. **번호는 저장하지 않습니다** — 각주의 번호는 다른 각주들 사이에서의 위치이고, 저장된 번호는 문단이 움직이는 순간 틀립니다. 제목 번호와 목차가 이미 따르는 규칙과 같습니다.

형식마다 놓이는 자리가 다릅니다.

| 형식 | 각주가 놓이는 곳 |
| --- | --- |
| **Word(.docx)** | **페이지 하단.** 워드의 진짜 각주입니다 |
| PDF | 문서 끝, 구분선 아래 |
| HTML | 문서 끝, 본문과 오가는 링크 포함 |
| Markdown | `[^1]` 참조와 문서 끝의 정의 |
| 텍스트 | `[1]` 표시와 끝의 「주석」 목록 |

**PDF가 페이지 하단이 아닌 이유**는 muni가 PDF를 만드는 방식 때문입니다. HTML을 브라우저로 인쇄하는데, 그 브라우저는 주석을 참조가 놓인 페이지에 배치하는 CSS를 구현하지 않습니다. 페이지 하단이 꼭 필요하면 Word로 내보내면 됩니다. 툴바 설명과 운영 안내에 그대로 적었습니다.

`.docx` 쪽은 `word/footnotes.xml`을 쓰고 본문에 `w:footnoteReference`를 넣습니다. 워드가 위에 긋는 구분선을 위한 separator 항목 두 개도 함께 씁니다 — 없으면 주석이 본문과 아무 경계 없이 붙습니다. 읽을 때는 그 두 항목(id 0과 1)을 건너뜁니다. 주석이 아니라 구분선이고, 그대로 읽으면 가져온 문서마다 빈 각주 두 개가 맨 앞에 생깁니다. 파일에 적힌 번호도 쓰지 않습니다 — 그건 그 문서에서의 번호입니다.

**내보내기가 각주를 모르면 본문에 섞입니다.** 인라인 처리의 기본 분기가 모르는 노드의 자식으로 내려가기 때문에, 주석의 글자가 그것이 설명하는 문장 한가운데 들어갑니다.

    집행률은 92%였다기획조정실 집계.. 전년보다 높다2025년 87%..

형식이 넷이라 넷 다 확인해야 했고, 넷 다 그랬습니다. 지금은 네 형식 모두에 대해 참조가 문장 뒤에 붙고 주석 내용이 본문에 섞이지 않는지 테스트가 확인합니다.

**번호는 렌더링 전에 사본에 찍습니다.** 렌더러가 세면서 매기려면 카운터가 필요한데, 동시 내보내기가 공유하는 카운터는 먼저 도착한 문서의 번호입니다. 같은 문서를 두 번 렌더링하면 같은 결과가 나오는지 테스트가 확인합니다.

편집기 화면에서는 각주가 괄호처럼 제자리에 보입니다. 편집기에는 페이지가 없어 하단에 둘 자리가 없고, 아무 데도 닿지 않는 번호는 글자 자체보다 못합니다 — 쓴 사람은 자기가 뭐라고 썼는지 읽어야 합니다.

## 업그레이드

마이그레이션과 설정 변경은 필요하지 않습니다.

```bash
gzip -dc muni-v0.16.0.tar.gz | docker load
docker compose -f compose.example.yaml --env-file .env up -d
```

**이미 muni에 들어와 있는 문서 중 위첨자를 잃은 것은 되돌아오지 않습니다.** 손실은 열던 시점에 일어났고 자동 저장이 확정했습니다. 원본 워드 파일이 남아 있다면 다시 가져오면 이번에는 그대로 들어옵니다.

## 오프라인 설치

릴리스 asset에는 `muni:v0.16.0` Docker 이미지가 포함되어 있습니다.

```bash
gzip -dc muni-v0.16.0.tar.gz | docker load
docker image inspect muni:v0.16.0

cp .env.example .env
# .env의 네 값을 운영 환경에 맞게 변경합니다.
docker compose -f compose.example.yaml --env-file .env up -d
```

애플리케이션이 반드시 필요로 하는 런타임 환경변수는 다음 네 개입니다.

| 환경변수                   | 설명                                 |
| -------------------------- | ------------------------------------ |
| `POSTGRES_DSN`             | PostgreSQL 접속 문자열               |
| `BOOTSTRAP_ADMIN`          | 최초 관리자 아이디 또는 이메일       |
| `BOOTSTRAP_ADMIN_PASSWORD` | 최초 관리자 비밀번호(12자 이상)      |
| `ENCRYPTION_KEY`           | base64로 인코딩한 32-byte master key |

PDF 변환 동작만 조정하는 선택 환경변수가 두 개 있습니다.

| 환경변수               | 기본값    | 설명                                       |
| ---------------------- | --------- | ------------------------------------------ |
| `MUNI_CHROMIUM_PATH`   | 자동 탐색 | PDF Export에 사용할 headless 브라우저 경로 |
| `MUNI_PDF_CONCURRENCY` | `2`       | 동시에 실행할 Chromium 프로세스 수(1~32)   |

## 운영 정보

- 서비스 포트: `8080`
- Liveness: `/healthz`
- Readiness: `/readyz`
- REST API: `/api/v1`
- 공개 링크: `/s/{token}` — 인증 없이 열리는 유일한 화면입니다
- OpenAPI: `/api/openapi.yaml` — 실제 라우트와 일치하며, 테스트가 그것을 지킵니다
- Prometheus: `/metrics` — 관리자 인증 필요
- MCP: `/mcp`
- 지원 DB: PostgreSQL 15 이상
- 이미지에는 PDF Export용 Chromium과 Noto CJK 글꼴이 포함되어 있습니다.
