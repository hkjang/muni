관리 기능을 고도화한 릴리스입니다. 관리자가 그동안 데이터베이스를 직접 만져야 했던 일들을 화면으로 옮기고, 쌓이기만 하던 데이터에 보존 정책을 붙였습니다.

## 추가

### 운영 현황

관리자가 `서비스 관리`를 열면 **설정 폼**이 나왔습니다. 운영자가 실제로 받는 질문에는 하나도 답하지 못하고, 알아보려면 설정을 만져보게 만드는 화면이었습니다.

이제 숫자로 엽니다.

- 사용자 수, 활성·정지·관리자, 최근 7일 로그인
- 워크스페이스와 문서 수, 이번 주에 쓰인 양, 휴지통과 버전 수
- 첨부 파일 용량, 열린 세션, 사용 중인 API key
- 승인 대기 중인 문서

옆에는 바깥과 연결되는 부분들이 **어떻게 설정돼 있는지** 보여줍니다. 데이터베이스, AI, OIDC, 발표자료 연동, PDF 내보내기. 설정을 읽어 판단할 뿐 아무 곳에도 호출하지 않습니다. 남의 게이트웨이를 기다리는 개요는 열리지 않는 개요이기 때문입니다. 실제 연결 시험은 원래 자리인 각 설정 화면의 연결 테스트 버튼에 그대로 있습니다.

기존 설정 화면은 `서비스 관리 → 서비스 설정`으로 옮겼습니다.

### 감사 로그 검색과 내보내기

마지막 100건만 보여주고 끝이었습니다. 감사 로그가 존재하는 이유인 질문 — **이 사람이 무엇을 했나**, **이 문서에 무슨 일이 있었나**, **이 기간에** — 에 답할 수 없었습니다.

이제 검색어, 대상 종류, 정확한 동작 이름, 기간으로 거르고 전체를 넘겨 봅니다. **CSV로 내려받을 수 있어** 물어본 사람에게 그대로 건넬 수 있습니다.

넘기기는 offset이 아니라 행 번호 기준입니다. 계속 쌓이는 로그에서 offset을 쓰면 읽는 도중 행이 밀립니다. 화면과 내려받기가 같은 쿼리를 쓰므로 "무엇을 걸렀는지"가 어긋날 수 없습니다.

### 워크스페이스

관리자도 자기가 속한 워크스페이스만 볼 수 있었습니다. 보통 전체 중 몇 개뿐입니다.

이제 전부 보이고, 소유자·구성원 수·문서 수·마지막 편집 시각이 함께 나옵니다. 아직 쓰이는 곳인지 판단하는 값들입니다.

### 문서 관리

문서에 닿는 모든 경로가 권한 검사를 거칩니다. 그래서 운영자가 받는 질문에 답할 화면이 없었습니다.

**소유권 이전** — 소유자가 떠나면 그 사람 문서를 아무도 공유·복원·삭제할 수 없게 됩니다. 지금까지는 데이터베이스에서 한 줄 고치는 일이었습니다. 넘길 때 새 소유자가 워크스페이스 구성원이 아니면 함께 추가합니다. 자기 목록에서 문서가 보이지 않는 소유자는 넘겨받은 것이 아니기 때문입니다. 문서를 열어 두고 있던 사람은 다시 연결되어, 방금 바뀐 권한으로 계속 작업하지 않습니다.

**완전 삭제** — 휴지통에 있는 문서만 지울 수 있습니다. 버전, 댓글, 제안, 첨부가 함께 사라집니다. 사용 중인 문서에서 바로 지우면 잘못 누른 한 번이 복구 불가가 되고, 휴지통이 그 확인 단계입니다. AI 호출 감사 기록은 문서보다 오래 남습니다. 그것이 감사 기록을 두는 이유입니다.

### 로그인 세션 관리

계정 정지는 있었지만 **로그아웃시킬 방법이 없었습니다.**

정지는 매 요청마다 계정을 다시 읽으므로 다음 요청부터 바로 막힙니다. 이 기능은 다른 경우를 위한 것입니다 — 기차에 두고 내린 노트북처럼, 계정은 그대로 두고 기기에서만 끊어야 할 때. 어디에서 로그인돼 있는지 보고, 한 번에 모두 종료합니다.

### 보존 정책

**아무것도 지워지지 않았습니다.** 휴지통에 버린 문서, 모든 문서의 모든 버전, 감사 로그와 AI 호출 기록이 무한정 쌓였습니다. 1년 돌린 설치에서는 디스크 문제이고, "무엇을 얼마나 보관하느냐"에 답할 수 없는 상태였습니다.

| 항목 | 설정 |
| --- | --- |
| 휴지통 | 지난 뒤 문서와 딸린 것 전부 삭제 |
| 버전 | 기간 + 항상 남길 개수 |
| 감사 로그 | 기간 |
| AI 호출 기록 | 기간 |

전부 일 단위이고 **0은 계속 보관**입니다. 지금까지 muni가 하던 그대로이므로, 값을 넣기 전까지 업그레이드로 달라지는 것은 없습니다.

하루 한 번 적용되고 **지금 실행** 버튼이 따로 있습니다. 정책을 막 설정한 관리자가 생각보다 많이 지워진다는 사실을 하루 뒤에 알게 되면 안 됩니다. 같은 이유로, 저장된 정책이 무엇을 얼마나 지울지 **미리 보여줍니다.**

버전 정리에서는 나이와 상관없이 세 가지가 남습니다.

- 문서별 가장 최근 N개
- 작성자가 **이름을 붙인 버전**
- 문서의 현재 버전

시계로 비울 수 있는 기록은 기록이 아닙니다. 그래서 5개 미만만 남기는 정책은 조용히 보정하지 않고 **거부합니다.**

만료된 세션은 정책과 관계없이 정리합니다. 어차피 누구도 인증할 수 없는 기록입니다.

## 업그레이드

데이터베이스 마이그레이션과 설정 변경은 필요하지 않습니다. 새 이미지로 교체하면 됩니다.

```bash
gzip -dc muni-v0.8.0.tar.gz | docker load
docker compose -f compose.example.yaml --env-file .env up -d
```

**보존 정책은 꺼진 상태로 시작합니다.** 관리자가 값을 넣기 전까지 아무것도 지워지지 않습니다. 값을 넣기 전에 미리보기로 규모를 확인하시고, 지워진 항목은 되돌릴 수 없다는 점을 유의하세요. 백업을 대신하지 않습니다.

## 오프라인 설치

릴리스 asset에는 `muni:v0.8.0` Docker 이미지가 포함되어 있습니다.

```bash
gzip -dc muni-v0.8.0.tar.gz | docker load
docker image inspect muni:v0.8.0

cp .env.example .env
# .env의 네 값을 운영 환경에 맞게 변경합니다.
docker compose -f compose.example.yaml --env-file .env up -d
```

애플리케이션이 반드시 필요로 하는 런타임 환경변수는 다음 네 개입니다.

| 환경변수                   | 설명                                 |
| -------------------------- | ------------------------------------ |
| `POSTGRES_DSN`             | PostgreSQL 접속 문자열               |
| `BOOTSTRAP_ADMIN`          | 최초 관리자 아이디 또는 이메일       |
| `BOOTSTRAP_ADMIN_PASSWORD` | 최초 관리자 비밀번호(12자 이상)      |
| `ENCRYPTION_KEY`           | base64로 인코딩한 32-byte master key |

PDF 변환 동작만 조정하는 선택 환경변수가 두 개 있습니다.

| 환경변수               | 기본값    | 설명                                       |
| ---------------------- | --------- | ------------------------------------------ |
| `MUNI_CHROMIUM_PATH`   | 자동 탐색 | PDF Export에 사용할 headless 브라우저 경로 |
| `MUNI_PDF_CONCURRENCY` | `2`       | 동시에 실행할 Chromium 프로세스 수(1~32)   |

## 운영 정보

- 서비스 포트: `8080`

- REST API: `/api/v1`
