muni 가 쓰는 `.hwpx` 를 **한글이 쓰는 모양 그대로** 고쳤고, 그 파일을 다른 구현으로 읽어 원본과 대조했습니다. 대조가 리더의 결함 셋과 빠진 것 셋을 찾아냈습니다 — 목록·머리말·꼬리말·표 캡션이 이제 들어오고, 목록과 머리말·꼬리말은 `.hwpx` 로 나가기도 합니다.

## 무엇을 확인했나

v0.19.1 은 실제 `.hwp` 열일곱 개를 `.hwpx` 로 써서 다시 읽으면 글자가 같다고 했습니다. 그것은 **muni 의 리더가 muni 의 리더를 검사한 것**이었습니다 — 쓴 파일이 한글에서 열리는지는 말해 주지 않습니다. 한글을 돌릴 수는 없으므로 두 가지로 대신했습니다.

1. **한글이 쓴 파일 열다섯 개에서 모양을 읽어 냈습니다.** 요소마다 한글이 어떤 자식을 어떤 차례로 쓰고 어떤 속성을 두는지 세었습니다 — 칸 1,294개, 문단 1,748개, 그림 29개, 표 98개에서. 그리고 muni 가 쓰는 것과 견줬습니다.
2. **다른 구현으로 읽었습니다.** [rhwp](https://github.com/edwardkim/rhwp) 를 빌드해 muni 가 쓴 열일곱 개를 전부 읽히고, 그것이 낸 글자를 원본 `.hwp` 에서 낸 글자와 대조했습니다.

## 쓰는 파일에서 고친 것

한글이 쓰는 것과 달랐던 자리입니다. 파서는 너그럽지만 한글의 로더는 그렇지 않을 수 있습니다.

- **글꼴을 이름으로 가리켰습니다.** `<hh:fontRef hangul="함초롬바탕">` — 한글은 머리의 글꼴 표에서 **번호**를 씁니다. 이제 글꼴 표를 쓰고 번호로 가리킵니다.
- **칸의 세로 정렬을 엉뚱한 요소에 두었습니다.** 한글은 `<hp:tc>` 가 아니라 그 안의 `<hp:subList>` 에 둡니다 — 실제 파일의 칸 1,294개 전부가 그렇고, `<hp:tc>` 에 둔 것은 하나도 없습니다.
- **칸 안의 차례가 거꾸로였습니다.** 한글은 문단 목록을 먼저, 주소·병합·크기·여백을 뒤에 씁니다. OWPML 은 순서가 있는 형식입니다.
- **문단의 여백·줄간격을 `switch` 밖에 썼습니다.** 한글은 단위 속성을 아는 리더와 모르는 리더용으로 두 벌을 `<hp:switch>` 안에 씁니다.
- **그림에 요소 열 개가 없었습니다.** 원본 크기, 현재 크기, 뒤집기, 회전, 렌더링 행렬, 자르기, 안쪽 여백, 치수, 효과, 바깥 여백 — 한글이 쓰는 그림 스물아홉 개 전부에 있습니다. id 도 이름이 아니라 번호입니다.
- **표에 속성 여덟 개가 없었고 높이가 0 이었습니다.** 한글이 쓰는 표 아흔여덟 개 전부에 있는 것들입니다. 높이는 문단마다 한 줄로 어림해 두고 한글이 다시 잡게 합니다.
- **참·거짓을 `true`/`false` 로 썼습니다.** 한글은 `1`/`0` 입니다.
- **문단에 번호와 표시가 없었습니다.** `id`, `pageBreak`, `columnBreak`, `merged` — 실제 문단 1,748개 전부에 있습니다.
- **구역 정의가 용지에서 끝났습니다.** 각주·미주 설정과 쪽 테두리 셋, 단 정의가 이어집니다.
- **부품 둘이 없었습니다.** `META-INF/container.rdf` 와 `Preview/PrvText.txt` — 한글이 쓴 열다섯 중 열넷이 둘 다 가지고 `container.xml` 에 적어 둡니다. 미리보기는 파일 탐색기가 문서를 열기 전에 보여 주는 글입니다.
- **가리키는 번호가 없는 것을 가리켰습니다.** `tabPrIDRef="0"` 에 탭 정의가 없었고, `borderFillIDRef="0"` 에 테두리가 없었습니다. 이제 셋 다 있습니다 — 문단용, 글자용, 표용.
- **판을 5.0.5 로 적었습니다.** 한글이 오늘 쓰는 것은 5.1.0 입니다. 낮은 판은 옛 방언을 뜻하고, 로더는 그렇게 읽을 자격이 있습니다.
- **목록을 글자로 썼습니다.** "• " 와 "1. " 을 글자 앞에 붙였습니다. 이제 머리에 글머리표와 번호 정의를 두고 문단 모양이 그것을 가리킵니다 — 한글이 목록을 두는 방식이고, 한글이 기호를 그립니다.

## 대조가 찾아낸 리더의 결함

한글이 쓰는 모양으로 쓰기 시작하자, muni 의 리더가 **한글이 쓴 모든 파일**에서 잃고 있던 것이 드러났습니다. 실제 파일로 확인한 v0.19.1 이 놓친 것들입니다 — 글자는 다 들어왔으므로 글자 대조는 통과했고, 서식은 대조하지 않았습니다.

- **글꼴이 "0" 이었습니다.** `fontRef` 의 번호를 이름으로 읽어, 한글이 쓴 모든 문서의 모든 런에 "0" 이나 "1" 이라는 글꼴이 붙었습니다. 이제 글꼴 표를 거칩니다.
- **가운데 정렬한 칸이 전부 위 정렬이었습니다.** 세로 정렬을 `<hp:tc>` 에서 찾았고, 한글은 거기에 쓰지 않습니다.
- **들여쓰기와 줄간격이 사라졌습니다.** 여백을 문단 모양의 직계 자식에서만 찾았고, 한글은 `<hp:switch>` 안에 둡니다.

## 대조가 찾아낸 빠진 것

rhwp 가 낸 글자와 muni 가 낸 글자를 열일곱 파일에서 대조했습니다.

- **목록.** `.hwp` 는 목록 요소가 없습니다 — 문단 모양이 "글머리표" 나 "번호" 라고 말하고, 깊이를 말합니다. 그 문단들의 연속을 목록으로 다시 세웁니다. 깊은 문단은 위 항목 안으로 들어가고, 얕아지면 닫힙니다. `.hwpx` 의 `<hh:heading type="BULLET">` 도 같습니다. 두 리더가 한 코드를 씁니다.
- **머리말·꼬리말.** 두 형식 모두 읽지 않았습니다. 이제 첫 머리말과 첫 꼬리말이 문서의 것으로 들어오고 — Word 에서 들어오는 것과 같은 자리 — `.hwpx` 로 나갈 때 함께 나갑니다.
- **표 캡션.** 캡션은 칸 주소가 없는 `LIST_HEADER` 입니다. 주소가 없다고 버렸습니다. 이제 표 뒤의 문단으로 옵니다.

열일곱 중 열둘이 글자까지 같습니다. 나머지 다섯의 차이는 rhwp 가 각주·개요 **번호**를 글자로 그리는 것과, `Textmail.hwp` 의 단추·확인란 이름 두 줄 — 문단이 아니라 서식 개체라 어느 문단에도 없는 글 — 입니다.

## 남긴 것

`MUNI_OUT=<dir>` 을 더하면 왕복 검사가 쓴 `.hwpx` 를 남깁니다. 한글에서 열어 보시고 어긋나는 곳을 알려 주시면 가장 도움이 됩니다 — 한글 자신이 여는지는 여전히 한글만이 말해 줄 수 있습니다.

```bash
MUNI_CORPUS=<dir> MUNI_OUT=<out> go test ./internal/hwpx/ -run RealRoundTrip -v
```

## 업그레이드

마이그레이션과 설정 변경은 필요하지 않습니다.

```bash
gzip -dc muni-v0.20.0.tar.gz | docker load
docker compose -f compose.example.yaml --env-file .env up -d
```

**`.hwpx` 를 가져오셨다면 다시 가져와 보세요.** 글꼴이 "0" 으로 붙어 있거나, 칸의 세로 정렬과 들여쓰기가 빠져 있을 수 있습니다. `.hwp`·`.hwpx` 의 목록·머리말·꼬리말·표 캡션은 이번에 처음 들어옵니다. **`.hwpx` 로 내보내셨다면 다시 내보내세요** — 이전 파일은 한글이 쓰는 모양이 아니었습니다.

## 오프라인 설치

릴리스 asset 에는 `muni:v0.20.0` Docker 이미지가 포함되어 있습니다.

```bash
gzip -dc muni-v0.20.0.tar.gz | docker load
docker image inspect muni:v0.20.0

cp .env.example .env
# .env의 네 값을 운영 환경에 맞게 변경합니다.
docker compose -f compose.example.yaml --env-file .env up -d
```

애플리케이션이 반드시 필요로 하는 런타임 환경변수는 다음 네 개입니다.

| 환경변수                   | 설명                                 |
| -------------------------- | ------------------------------------ |
| `POSTGRES_DSN`             | PostgreSQL 접속 문자열               |
| `BOOTSTRAP_ADMIN`          | 최초 관리자 아이디 또는 이메일       |
| `BOOTSTRAP_ADMIN_PASSWORD` | 최초 관리자 비밀번호(12자 이상)      |
| `ENCRYPTION_KEY`           | base64로 인코딩한 32-byte master key |

PDF 변환 동작만 조정하는 선택 환경변수가 두 개 있습니다.

| 환경변수               | 기본값    | 설명                                       |
| ---------------------- | --------- | ------------------------------------------ |
| `MUNI_CHROMIUM_PATH`   | 자동 탐색 | PDF Export에 사용할 headless 브라우저 경로 |
| `MUNI_PDF_CONCURRENCY` | `2`       | 동시에 실행할 Chromium 프로세스 수(1~32)   |

## 운영 정보

- 서비스 포트: `8080`
- Liveness: `/healthz`
- Readiness: `/readyz`
- REST API: `/api/v1`
- 공개 링크: `/s/{token}` — 인증 없이 열리는 유일한 화면입니다
- OpenAPI: `/api/openapi.yaml` — 실제 라우트와 일치하며, 테스트가 그것을 지킵니다
- Prometheus: `/metrics` — 관리자 인증 필요
- MCP: `/mcp`
- 지원 DB: PostgreSQL 15 이상
- 이미지에는 PDF Export용 Chromium과 Noto CJK 글꼴이 포함되어 있습니다.
