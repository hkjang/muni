v0.17.0 에서 새로 생긴 문제 하나가 문서를 잘라내고 있었습니다. 그리고 워드 문서를 읽을 때 오래전부터 잃고 있던 것들을 함께 고쳤습니다.

## v0.17.0 에서 생긴 문제

### 목차가 뒤의 본문을 통째로 지우고 있었습니다

v0.17.0 이 워드의 목차 필드를 읽기 시작하면서 들어온 문제입니다.

워드는 목차를 **필드로 감싸서** 씁니다. 여는 표시가 한 문단에 있고, 마지막으로 계산해 둔 항목들이 뒤따르고, 닫는 표시가 다시 한 문단에 있습니다. muni 는 여는 표시를 보면 "지금 목차 안"이라고 표시해 두고 닫는 표시가 올 때까지 문단을 건너뛰었습니다.

**그런데 닫는 표시가 표 안에 있을 수 있습니다.** 목차를 표로 짜 넣은 서식은 한국 보고서 양식에 드물지 않고, 표 안은 muni 가 따로 들어가서 읽는 곳이라 그 닫는 표시가 바깥의 표시에 닿지 않습니다. 그러면 **그 뒤의 모든 문단이 사라진 채로 가져오기가 성공합니다.** 문서가 목차에서 끝나 있고, 아무것도 잘못되었다고 말하지 않습니다.

목차의 범위를 **건너뛰기 전에 먼저 계산**하도록 바꿨습니다. 닫는 표시를 찾지 못하면 여는 문단 하나만 버립니다 — 망가진 필드의 캐시를 잃는 것이 그 뒤의 문서 전체를 잃는 것보다 작은 잘못입니다.

### 스타일이 정한 서식을 절반만 읽고 있었습니다

v0.17.0 은 문단·문자 스타일을 읽기 시작했지만, **요소 단위로** 읽었습니다. OOXML 은 **속성 단위로** 상속합니다.

스타일이 `<w:spacing w:line="384"/>`(줄간격 1.6)을 정하고 문단이 `<w:spacing w:before="240"/>`(문단 앞 간격)만 정했다면, 워드는 1.6 으로 그립니다 — 문단은 줄간격에 대해 아무 말도 하지 않았으니까요. muni 는 문단의 것을 취하고 스타일의 것을 통째로 버려서 줄간격을 잃었습니다. **한 가지만 조정한 문단이 흔한 경우이지 예외가 아니므로**, 스타일을 읽기 시작한 그 작업이 실제 문서 대부분에서 빗나가고 있었습니다.

런에서도 같습니다. 한국어 문서는 런에 `<w:rFonts w:hint="eastAsia"/>` 만 적는 일이 잦은데, 그것이 스타일의 글꼴을 통째로 막고 있었습니다.

### 하이퍼링크가 워드의 파랑으로 굳었습니다

v0.17.0 이 문자 스타일을 읽기 시작하면서, 워드의 `Hyperlink` 스타일이 가진 `0563C1` 이 링크 글자에 **박힌 색**으로 따라 들어왔습니다. 그러면 그 링크는 편집기에서도 내보낸 파일에서도 muni 의 링크 색을 따르지 않습니다. 이제 스타일이 그리는 밑줄은 받고 색은 muni 가 정합니다.

### 그 밖에

- **표의 머리글 행이 한 줄 아래로 내려가는 경우**가 있었습니다. 첫 `w:tr` 이 칸을 하나도 만들지 않으면(세로 병합의 이어지는 칸만 있는 행) 그 다음 자료 행이 머리글이 되었습니다.
- **제목 안의 그림이 제목을 둘로 쪼갰습니다.** 개요·목차·번호가 모두 쓴 사람이 만들지 않은 항목을 하나씩 더 갖게 됩니다. 이제 그림은 제목 뒤로 나갑니다.
- **표 칸의 세로 정렬을 muni 가 지어내고 있었습니다.** 내보낼 때 모든 칸에 `가운데`를 적었습니다. 화면과 PDF 는 처음부터 `위`로 그리고 있었으므로, muni 에서 만든 표가 화면과 워드에서 다르게 보였습니다. 이제 워드에서 정한 값을 읽고, 아무 말이 없는 칸은 화면과 같은 `위`로 내보냅니다.

## 예전부터 있던 문제

### 워드 문서의 첫 번째 각주가 사라지고 있었습니다

주석을 읽을 때 번호 0 과 1 을 구분선으로 보고 건너뛰었습니다. **muni 자신이 쓴 파일에서는 맞습니다** — muni 는 구분선을 0 과 1 로 적고 실제 주석을 2 부터 시작합니다. **워드는 구분선을 -1 과 0 으로 적고 첫 주석을 1 로 적습니다.**

그래서 워드가 만든 문서를 가져올 때마다 첫 번째 각주가 본문에서도 사라졌습니다 — 번호도, 내용도. 구분선은 번호가 아니라 `w:type` 이 말해 주고, 그 검사는 이미 위에 있었습니다.

### 텍스트 상자 안의 글자가 사라졌습니다

붙임 표시, 서명 옆의 직인, 여백의 메모 — 한국 공문서가 상자에 넣어 두는 것들입니다. 상자는 그림으로 도착하는데, muni 는 그림인지 묻고 아니라고 답이 나오면 아무것도 남기지 않았습니다. **글자가 있던 자리에 빈 문단만 남았습니다.**

이제 글자를 글자로 읽습니다. 두 줄짜리 직인은 두 줄로 남습니다 — 한 줄로 읽은 직인은 다른 직인입니다. 묶여 있는 상자도 모두 읽습니다.

### 미주가 사라졌습니다

muni 에는 주석이 한 종류입니다. 각주와 미주는 **어디에 인쇄되는가**만 다르고, muni 는 이미 PDF 에서 주석을 문서 끝에 둡니다. 미주를 각주로 읽으면 글자와 그것이 붙어 있던 자리가 남고, 버리면 둘 다 잃습니다.

### 두 줄로 쓴 주석이 한 줄로 붙었습니다

인용 하나와 그에 대한 한마디 — 주석의 흔한 모양입니다. 주석 전체를 한 덩어리로 읽어서 `기획조정실(2026)같은 자료 12쪽` 이 되었습니다. 글자는 다 있고 문장이 없어진 경우입니다.

그 아래에 두 가지가 더 있었습니다. **`PlainText` 가 줄바꿈을 본 적이 없어서** 검색 색인과 미리보기에서도 줄바꿈 양쪽이 붙어 있었고, 주석 글자를 조각마다 따로 물어보느라 조각을 떼어 놓는 바로 그것을 버리고 있었습니다.

### 머리글에 필드가 있으면 머리글 전체를 잃었습니다

워드의 머리글은 `[STYLEREF] · 대외비` 처럼 필드 뒤에 진짜 글자가 오는 일이 흔합니다. 첫 필드에서 읽기를 멈추고 있어서 **대외비를 필드와 함께 잃었습니다.** 이제 필드가 계산해 둔 값만 버리고 주위의 글자는 남깁니다. 필드에 붙어 있던 구분 기호는 필드와 함께 가고, 쓴 사람이 낱말 사이에 찍은 기호는 그대로 둡니다.

## 다시 생기지 않도록

이 릴리스의 문제 대부분은 **v0.17.0 을 만든 작업을 스스로 다시 읽어서** 찾았습니다. 새 기능을 하나 더 찾는 것보다 방금 쓴 코드를 검토하는 편이 나은 시점이 있고, 그 시점이었습니다.

편집기 쪽에는 검사가 하나 늘었습니다. `setContent` 는 **검사하지 않습니다** — ProseMirror 는 JSON 에서 노드를 만들고, 잘못된 곳은 나중에 그것을 건드리는 첫 편집에서 터집니다. 문서가 열리고 저장되면서도 쓸 수 없는 상태가 될 수 있다는 뜻입니다. 이제 서버가 만들 수 있는 문서를 편집기에 넣고 `doc.check()` 를 부릅니다.

## 업그레이드

마이그레이션과 설정 변경은 필요하지 않습니다.

```bash
gzip -dc muni-v0.17.1.tar.gz | docker load
docker compose -f compose.example.yaml --env-file .env up -d
```

**v0.17.0 에서 목차가 있는 워드 문서를 가져오셨다면 그 문서를 다시 확인해 주세요.** 목차 뒤의 본문이 잘려 있을 수 있고, 그 손실은 가져오던 시점에 일어났으므로 되돌아오지 않습니다. **원본 워드 파일이 남아 있다면 다시 가져오면 이번에는 그대로 들어옵니다.**

## 오프라인 설치

릴리스 asset 에는 `muni:v0.17.1` Docker 이미지가 포함되어 있습니다.

```bash
gzip -dc muni-v0.17.1.tar.gz | docker load
docker image inspect muni:v0.17.1

cp .env.example .env
# .env의 네 값을 운영 환경에 맞게 변경합니다.
docker compose -f compose.example.yaml --env-file .env up -d
```

애플리케이션이 반드시 필요로 하는 런타임 환경변수는 다음 네 개입니다.

| 환경변수                   | 설명                                 |
| -------------------------- | ------------------------------------ |
| `POSTGRES_DSN`             | PostgreSQL 접속 문자열               |
| `BOOTSTRAP_ADMIN`          | 최초 관리자 아이디 또는 이메일       |
| `BOOTSTRAP_ADMIN_PASSWORD` | 최초 관리자 비밀번호(12자 이상)      |
| `ENCRYPTION_KEY`           | base64로 인코딩한 32-byte master key |

PDF 변환 동작만 조정하는 선택 환경변수가 두 개 있습니다.

| 환경변수               | 기본값    | 설명                                       |
| ---------------------- | --------- | ------------------------------------------ |
| `MUNI_CHROMIUM_PATH`   | 자동 탐색 | PDF Export에 사용할 headless 브라우저 경로 |
| `MUNI_PDF_CONCURRENCY` | `2`       | 동시에 실행할 Chromium 프로세스 수(1~32)   |

## 운영 정보

- 서비스 포트: `8080`
- Liveness: `/healthz`
- Readiness: `/readyz`
- REST API: `/api/v1`
- 공개 링크: `/s/{token}` — 인증 없이 열리는 유일한 화면입니다
- OpenAPI: `/api/openapi.yaml` — 실제 라우트와 일치하며, 테스트가 그것을 지킵니다
- Prometheus: `/metrics` — 관리자 인증 필요
- MCP: `/mcp`
- 지원 DB: PostgreSQL 15 이상
- 이미지에는 PDF Export용 Chromium과 Noto CJK 글꼴이 포함되어 있습니다.
