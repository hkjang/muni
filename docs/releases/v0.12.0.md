Prometheus로 muni를 감시할 수 있게 되었습니다. 쓰지 않으신다면 이 릴리스는 아무것도 바꾸지 않습니다.

## 추가

### 지표 엔드포인트

muni는 로그를 남기고 있었지만, 그 로그로 답할 수 있는 질문은 "방금 무슨 일이 있었나"뿐이었습니다. "어제보다 느려졌나", "알림이 쌓이고 있나", "PDF 내보내기가 줄을 서고 있나" — 이런 것들은 사람이 눈치채기 전에는 아무도 몰랐습니다.

`GET /metrics`가 Prometheus 형식으로 지금 상태를 내놓습니다.

| 지표 | 뜻 |
| --- | --- |
| `muni_http_requests_total{method,status}` | 처리한 요청 수 |
| `muni_http_request_duration_seconds` | 응답 시간 히스토그램 |
| `muni_documents`, `muni_users`, `muni_sessions_open` | 규모 |
| `muni_collab_documents_open`, `muni_collab_connections` | 지금 편집 중인 것 |
| `muni_approvals_pending` | 결재 대기 |
| `muni_notifications_unsent` | 발송되지 못하고 남은 알림 |
| `muni_ai_calls_last_24h`, `muni_ai_failures_last_24h` | 하루치 AI 호출과 실패 |
| `muni_pdf_renders_in_progress`, `muni_pdf_renders_limit` | 앞이 뒤에 붙어 있으면 PDF가 줄을 서고 있다는 뜻입니다 |
| `muni_attachment_bytes`, `muni_goroutines`, `muni_memory_bytes` | 자원 |

세 가지를 의도적으로 정했습니다.

**관리자 인증 뒤에 둡니다.** 지표에는 사용자 수와 문서 수가 들어 있습니다. 사내망이라도 열어둘 이유가 없고, muni에는 이미 API 키가 있으므로 새로운 인증 수단을 만들 필요도 없었습니다. `서비스 관리 → API 키`에서 `api:read` 권한의 키를 만들어 Prometheus의 `authorization.credentials`에 넣으십시오.

**라벨은 메서드와 상태 계열(`2xx`·`4xx`·`5xx`)까지만 붙입니다.** 문서 ID나 사용자별로 나누고 싶은 유혹이 있지만, 그렇게 하면 문서가 늘어나는 만큼 시계열이 늘어나 muni보다 Prometheus 쪽이 먼저 무너집니다. 경로도 패턴이 아닌 실제 주소로 나뉘면 같은 일이 벌어지므로 넣지 않았습니다.

**수를 세는 질의는 30초 캐시합니다.** 서버를 여러 대 두고 15초마다 긁으면 `count(*)` 열한 개가 그 간격으로 DB에 갑니다. 지표를 보려다 지표가 보는 대상을 느리게 만드는 셈입니다. 그래서 스크레이프 간격을 30초보다 촘촘히 잡아도 값이 더 자주 바뀌지는 않습니다.

설정 예시와 경보 예시는 [운영 안내](https://github.com/hkjang/muni/blob/v0.12.0/docs/OPERATIONS.md)의 「지표 수집」에 있습니다.

## 수정

### 요청 시간을 재면서 스트리밍을 깨뜨리지 않기

응답 시간을 재려면 `ResponseWriter`를 감싸야 합니다. 그런데 AI 답변 스트리밍은 `http.Flusher`를, 협업 소켓은 `http.Hijacker`를 **타입 단언으로** 찾습니다. 감싸기만 하고 그 둘을 넘겨주지 않으면 AI 답변은 조용히 버퍼링되어 한꺼번에 나타나고, 협업 소켓은 업그레이드되지 않습니다. 어느 쪽도 오류를 내지 않기 때문에 눈치채기 어려운 종류의 고장입니다.

위임을 넣었고, 감싼 응답이 여전히 두 인터페이스를 만족하는지 테스트가 확인합니다. 이 릴리스에서 새로 생긴 문제였고, 나가기 전에 막았습니다.

## 업그레이드

데이터베이스 마이그레이션과 설정 변경은 필요하지 않습니다. Prometheus를 쓰지 않으면 아무 동작도 달라지지 않습니다 — 긁지 않으면 지표는 계산되지 않습니다.

```bash
gzip -dc muni-v0.12.0.tar.gz | docker load
docker compose -f compose.example.yaml --env-file .env up -d
```

## 오프라인 설치

릴리스 asset에는 `muni:v0.12.0` Docker 이미지가 포함되어 있습니다.

```bash
gzip -dc muni-v0.12.0.tar.gz | docker load
docker image inspect muni:v0.12.0

cp .env.example .env
# .env의 네 값을 운영 환경에 맞게 변경합니다.
docker compose -f compose.example.yaml --env-file .env up -d
```

애플리케이션이 반드시 필요로 하는 런타임 환경변수는 다음 네 개입니다.

| 환경변수                   | 설명                                 |
| -------------------------- | ------------------------------------ |
| `POSTGRES_DSN`             | PostgreSQL 접속 문자열               |
| `BOOTSTRAP_ADMIN`          | 최초 관리자 아이디 또는 이메일       |
| `BOOTSTRAP_ADMIN_PASSWORD` | 최초 관리자 비밀번호(12자 이상)      |
| `ENCRYPTION_KEY`           | base64로 인코딩한 32-byte master key |

PDF 변환 동작만 조정하는 선택 환경변수가 두 개 있습니다.

| 환경변수               | 기본값    | 설명                                       |
| ---------------------- | --------- | ------------------------------------------ |
| `MUNI_CHROMIUM_PATH`   | 자동 탐색 | PDF Export에 사용할 headless 브라우저 경로 |
| `MUNI_PDF_CONCURRENCY` | `2`       | 동시에 실행할 Chromium 프로세스 수(1~32)   |

## 운영 정보

- 서비스 포트: `8080`
- Liveness: `/healthz`
- Readiness: `/readyz`
- REST API: `/api/v1`
- OpenAPI: `/api/openapi.yaml` — 실제 라우트와 일치하며, 테스트가 그것을 지킵니다
- Prometheus: `/metrics` — 관리자 인증 필요
- MCP: `/mcp`
- 지원 DB: PostgreSQL 15 이상
- 이미지에는 PDF Export용 Chromium과 Noto CJK 글꼴이 포함되어 있습니다.

## 릴리스 파일 검증

- 파일: `muni-v0.12.0.tar.gz`
- 크기: 릴리스 게시 후 기재
- SHA-256: 릴리스 게시 후 기재
- 내부 이미지 태그: `muni:v0.12.0`

```bash
sha256sum muni-v0.12.0.tar.gz
```
