사내 메일 서버로 알림을 보낼 수 있게 되었습니다. 비밀번호 변경과 워크스페이스 소유권 이전도 함께 들어갔습니다.

## 추가

### 사내 메일 알림

알림은 처음부터 기록되고 있었지만 **한 번도 밖으로 나간 적이 없었습니다.** 검토 요청은 결재할 사람이 그날 muni를 열어야만 닿았습니다.

`서비스 관리 → 메일 알림`에서 회사 메일 서버를 지정합니다.

| 항목 | 설명 |
| --- | --- |
| 주소·포트 | 사내 SMTP 서버 |
| 보안 | STARTTLS(587), TLS(465), 사용 안 함 |
| 계정·비밀번호 | 필요한 경우 |
| 보내는 주소·이름 | 비우면 계정 주소를 사용 |
| 서비스 주소 | 메일 속 링크가 향할 곳 |

**내 주소로 시험 메일 보내기** 버튼이 있습니다. 거의 다 맞은 설정과 맞은 설정은 겉보기가 똑같아서, 한 통 보내보는 것 말고는 확인할 방법이 없습니다.

사설 인증기관을 쓰는 사내 서버가 흔하므로 **인증서 검증 생략** 옵션도 있습니다. 루트 인증서를 설치할 수 없는 운영자가 그 이유로 메일을 못 켜서는 안 되기 때문입니다.

**muni가 쓰는 메일 서버는 여기 적은 것 하나뿐입니다.** 외부 발송 서비스로 나가는 연결은 없습니다. 폐쇄망에서 작동하는 유일한 구성입니다.

#### 무엇이 발송되나

muni가 이미 기록하던 알림입니다 — 검토 요청, 승인 결과, 멘션.

각 처리 지점에 발송 코드를 붙이는 대신 **알림 테이블 위의 발송함**으로 만들었습니다.

- 요청 처리를 막지 않습니다.
- 실패는 다시 시도합니다.
- muni가 기록하지 않은 알림은 메일로 나갈 수 없습니다.

시도 횟수는 보내기 **전에** 올립니다. 그러지 않으면 받지 않는 주소를 매분 영원히 재시도합니다. 하루가 지난 알림은 보내지 않습니다. 장애에서 복구된 뒤 백 통이 한꺼번에 도착하면 안 되기 때문입니다.

본문에는 알림 문구와 링크만 담고 **문서 내용은 담지 않습니다.** 알림 메일이 문서를 실어 나르면, 받는 사람이 그 메일을 어디로 전달하든 내용도 함께 갑니다.

#### 검증에서 드러난 것

프로토콜을 실제로 주고받는 SMTP 서버를 테스트 안에 띄워 확인했고, 두 가지를 고쳤습니다.

- **헤더 인젝션** — 보내는 사람 이름이나 받는 주소에 줄바꿈이 있으면 남의 메일에 `Bcc:` 같은 헤더를 끼워 넣을 수 있었습니다. 헤더에 들어가는 모든 값을 한 줄로 정리합니다.
- **평문 연결에서의 인증** — PLAIN과 LOGIN을 모두 구현하되, 둘 다 암호화된 연결에서만 계정 정보를 보냅니다.

### 비밀번호 변경

**바꾸는 방법이 아예 없었습니다.** 관리자가 초기화하는 것도, 본인이 바꾸는 것도요. 로컬 계정은 만들어질 때 받은 비밀번호를 계정이 존재하는 내내 유지했습니다. 누가 골라서 그렇게 한 정책이 아니라 만들어지지 않았을 뿐이고, 월요일 아침에 잠긴 계정의 해법은 argon2 해시를 데이터베이스에 손으로 써넣는 것이었습니다.

- **본인 변경** (`개인 설정`) — 현재 비밀번호를 확인하고, **지금 보고 있는 세션만 남긴 채** 다른 로그인을 모두 종료합니다.
- **관리자 초기화** (`사용자 관리`) — 그 계정의 세션을 전부 종료합니다. 초기화는 보통 무슨 일이 있어서 하는 것이기 때문입니다.

조건은 길이 12자뿐입니다. 최초 관리자 비밀번호에 적용되는 것과 같은 규칙이고, **바이트가 아니라 글자로 셉니다.** 한글 12자는 36바이트지만 12자입니다.

SSO로 로그인하는 계정에는 인증 제공자에서 바꾸라고 안내합니다. 아무도 요청하지 않은 두 번째 출입구를 만들지 않습니다.

### 워크스페이스 소유권과 정리

소유자가 떠난 팀은 사람을 추가할 수도, 워크스페이스 설정을 바꿀 수도 없었습니다.

**소유권 이전** — 새 소유자는 워크스페이스 구성원으로 등록되고 OWNER 역할을 받습니다. 관리할 수 없는 것을 소유하게 두지 않기 위해서입니다.

**사용 중단** — 문서는 사라지지 않고 **휴지통으로** 갑니다. 보존 정책이 지우라고 지시받지 않은 것은 사라지지 않습니다. 워크스페이스는 되돌릴 수 있고, 문서는 휴지통에서 따로 되살립니다. 어느 것을 되살릴지는 추측할 일이 아니라 결정할 일이기 때문입니다.

승인 대기 중인 문서가 있으면 정리되지 않습니다. 검토는 다른 사람이 내릴 결정입니다. 개인 워크스페이스는 대상이 아닙니다.

## 업그레이드

데이터베이스 마이그레이션이 하나 추가됩니다(`007_notification_email.sql`). 서버가 시작할 때 자동으로 적용되며, `notifications` 표에 열 두 개와 인덱스 하나를 추가할 뿐 기존 데이터를 바꾸지 않습니다.

```bash
gzip -dc muni-v0.9.0.tar.gz | docker load
docker compose -f compose.example.yaml --env-file .env up -d
```

**메일 알림은 꺼진 상태로 시작합니다.** 관리자가 메일 서버를 지정하기 전까지 아무것도 발송되지 않습니다. 켜면 그 시점부터 하루 이내에 쌓인 알림이 발송 대상이 됩니다.

## 오프라인 설치

릴리스 asset에는 `muni:v0.9.0` Docker 이미지가 포함되어 있습니다.

```bash
gzip -dc muni-v0.9.0.tar.gz | docker load
docker image inspect muni:v0.9.0

cp .env.example .env
# .env의 네 값을 운영 환경에 맞게 변경합니다.
docker compose -f compose.example.yaml --env-file .env up -d
```

애플리케이션이 반드시 필요로 하는 런타임 환경변수는 다음 네 개입니다.

| 환경변수                   | 설명                                 |
| -------------------------- | ------------------------------------ |
| `POSTGRES_DSN`             | PostgreSQL 접속 문자열               |
| `BOOTSTRAP_ADMIN`          | 최초 관리자 아이디 또는 이메일       |
| `BOOTSTRAP_ADMIN_PASSWORD` | 최초 관리자 비밀번호(12자 이상)      |
| `ENCRYPTION_KEY`           | base64로 인코딩한 32-byte master key |

PDF 변환 동작만 조정하는 선택 환경변수가 두 개 있습니다.

| 환경변수               | 기본값    | 설명                                       |
| ---------------------- | --------- | ------------------------------------------ |
| `MUNI_CHROMIUM_PATH`   | 자동 탐색 | PDF Export에 사용할 headless 브라우저 경로 |
| `MUNI_PDF_CONCURRENCY` | `2`       | 동시에 실행할 Chromium 프로세스 수(1~32)   |

메일 서버는 환경변수가 아니라 관리자 화면에서 설정합니다. 비밀번호는 다른 비밀값과 같은 방식으로 암호화되어 저장됩니다.
