muni 가 한글 문서를 읽습니다. `.hwp` 와 `.hwpx` 둘 다입니다 — 한국 사무실이 쓰는 형식을, 한국 사무실을 위한 도구가 읽지 못하고 있었습니다.

그리고 마크다운을 붙여넣으면 서식이 되고, mermaid 코드 블록이 도형으로 그려집니다.

## 추가

### 한글 문서 가져오기 (.hwp · .hwpx)

**`.hwpx`** 는 한글이 쓰는 XML 형식입니다. `.docx` 처럼 XML 을 담은 zip 이라 읽는 방식도 비슷합니다 — 문단, 런과 그 서식, 표(가로·세로 병합, 칸 음영·세로 정렬), 그림, 제목 단계(개요 1~7), 용지 방향.

**한글의 런에는 서식이 하나도 적혀 있지 않습니다.** `charPrIDRef="7"` 하나만 있고, 그 번호가 무엇을 뜻하는지는 `Contents/header.xml` 에 있습니다. muni 가 워드 스타일을 통째로 잃고 있던 것과 **똑같은 모양**이라 — 서식이 붙은 자리만 읽고 서식이 적힌 곳은 읽지 않는 것 — 이 가져오기는 머리부터 읽습니다. 문단의 정렬·들여쓰기·줄간격도 같습니다.

**`.hwp`** 는 그 이전의 이진 형식이고, 몇 년 넘은 한국 문서는 대개 이쪽입니다. 글자가 나오기까지 세 겹을 벗겨야 합니다.

| 겹 | 무엇 |
| --- | --- |
| OLE2 복합 파일 | 파일 하나 안의 작은 파일 시스템 — 섹터 표, 디렉터리 트리, 그것을 따라 이어진 스트림 |
| raw deflate | zlib 껍데기가 **없습니다.** zlib 리더는 멀쩡한 파일에 "invalid header" 를 냅니다 |
| 레코드 | `uint32` 하나가 종류·깊이·길이를 함께 나릅니다. 길이가 `0xFFF` 면 진짜 길이는 다음 `uint32` 입니다 |

읽는 것: 글자와 문단, 굵게·기울임·밑줄·취소선, 문단 정렬·들여쓰기, 제목 단계, 표(가로·세로 병합), 그림. **암호가 걸린 문서는 무엇이 문제인지 말하고 거절합니다** — 깨진 글자로 가져오는 것보다 낫습니다.

아직 읽지 않는 것: 줄간격, 목록, 하이퍼링크. **내보내기는 두 형식 모두 아직입니다.**

#### 형식 문서가 놓은 덫

레코드는 각자 깊이를 지니고 한 줄로 늘어서 있습니다. 그것을 트리로 되돌려야 무엇이 무엇에 속하는지 알 수 있습니다 — 문단의 글자와 서식, 표의 칸, 칸 안의 문단이 전부 그렇습니다.

문단 글자 안의 제어 표시는 형식 문서에 **크기 8** 이라고 적혀 있고, **8 WCHAR 즉 16바이트**를 뜻합니다. 8바이트를 건너뛰면 표시 한가운데에 내려앉아 그 뒷부분을 글자로 읽고, 문서에 없던 한자가 흩뿌려집니다.

그리고 **서식이 가리키는 위치도 그 8을 셉니다.** 살아남은 글자만 세면 첫 표나 그림 뒤의 서식이 전부 엉뚱한 낱말에 붙습니다. 표시 하나를 사이에 두고 굵기가 옮겨가는지 확인하는 테스트를 두었고, 세는 방식을 일부러 망가뜨려 그 테스트가 잡는지 확인했습니다.

### mermaid 도형

`mermaid` 언어를 지정한 코드 블록이 도형으로 그려집니다.

**도형을 따로 만든 노드가 아니라 코드 블록으로 둔 것이 설계의 전부입니다.** muni 가 이미 가진 모든 경로 — 편집기 스키마, `.docx` 내보내기, 마크다운 펜스, 텍스트 내보내기 — 가 코드 블록과 그 언어를 아무것도 새로 배우지 않고 나릅니다. 그래서 도형은 그 모든 곳을 **그것이 쓴 글 그대로** 통과합니다.

| 어디서 | 무엇이 나오는가 |
| --- | --- |
| 편집기 | 설명하는 글 **아래에** 도형. 둘 다입니다 — 글을 그림으로 바꿔치우면 도형을 고칠 방법이 편집기에게 글을 돌려달라고 하는 것뿐입니다 |
| HTML | 그림. 그리는 라이브러리를 파일 안에 넣으므로 네트워크가 없는 곳에서도 같게 그려집니다 |
| PDF | 그림. **다 그릴 때까지 기다렸다가** 인쇄합니다 |
| 그 밖 | 코드 그대로. 도형이 말하는 바가 곧 그 글입니다 |

**PDF 가 기다리는 이유**는, 기다리지 않으면 그리는 도중에 인쇄되어 그림이 **파일에서 빠지기** 때문입니다 — 틀리게 나오는 것이 아니라 없어지고, PDF 는 무엇이 빠졌다고 말하지 않습니다. 기다림에는 한계를 두어 파싱되지 않는 도형 하나가 워커를 붙잡지 못하게 했습니다.

라이브러리는 **문서에 그릴 것이 있을 때만** 실립니다. 3.5MB 짜리이고, 도형 없는 보고서가 그만큼 커질 이유는 없습니다. 저장소에는 넣지 않고 빌드할 때 넣습니다 — 남의 압축된 출력 3.5MB 를 저장소가 지고 다닐 이유도 없습니다.

### 마크다운 붙여넣기

마크다운을 붙여넣으면 글자가 그대로 들어왔습니다. `## 제목` 은 샵 두 개로 시작하는 줄이었습니다.

이제 제목·목록·인용·표·코드·강조가 됩니다. 필요한 것은 muni 에 이미 다 있었습니다 — 마크다운 리더, 편집기 내용으로 바꾸는 변환기, 서식이 들어 있는지 판단하는 검사 — 전부 AI 패널을 위해 만들어져 붙여넣기에서는 닿을 수 없었습니다.

**코드 블록 안에서는 하지 않습니다.** 거기 붙여넣은 마크다운은 코드 예시이고, ```를 지시로 읽는 것은 반대 방향의 같은 잘못입니다.

## 수정

v0.17.0 을 만든 작업을 스스로 다시 읽어 v0.17.1 을 냈고, **그 v0.17.1 을 다시 읽어 이번 것들을 찾았습니다.**

### 쓴 사람이 끈 굵기를 스타일이 되살렸습니다

OOXML 의 켜고 끄는 속성은 **요소 자체가 값**입니다. `<w:b/>` 는 굵게이고 `<w:b w:val="0"/>` 는 굵지 않게입니다. v0.17.1 이 스타일 상속을 속성 단위로 고치면서, 스타일의 `w:val="0"` 을 런이 맨몸으로 쓴 `<w:b/>` 에 합쳐 **쓴 사람의 굵기를 껐습니다.** 고치려던 것의 정반대입니다.

### 그 밖에

- **한글 런이 라틴 글꼴로 이름표가 붙었습니다.** 바탕체만 적은 런이 Cambria 만 적은 스타일 아래에서 Cambria 로 나왔습니다.
- **바닥글의 띄어쓰기가 먹혔습니다.** `총 [NUMPAGES] 쪽` 이 `총쪽` 이 되고, `홍길동 (기획조정실) / [PAGE]` 는 닫는 괄호를 잃었습니다.
- **표로 짠 목차가 그대로 남았습니다.** 굳어버린 쪽 번호 표가 그것을 대신할 목차 노드 옆에 진짜 표로 들어왔습니다.
- **블록 자리의 도형이 두 번 읽혔습니다.** 직인이 문서에 두 번 찍혔습니다.
- **그림만 있는 제목이 빈 제목을 남겼습니다.** 표지의 로고 위에 제목의 여백과 굵기가 그대로 그려졌습니다.

## 알아 두실 것

**두 한글 리더는 아직 진짜 한글 파일로 확인되지 않았습니다.** 모든 테스트가 형식 문서를 보고 **직접 만든 파일**로 돌아갑니다 — muni 가 `.hwp` 도 `.hwpx` 도 쓰지 않으므로 그것 말고는 방법이 없고, 워드 쪽에서 같은 방식이 실제 결함 여섯 개를 찾아냈습니다. 그래도 한글 오피스가 실제로 저장한 문서를 통과시켜 본 것과는 다릅니다. **가지고 계신 `.hwp`·`.hwpx` 로 시도해 보시고 어긋나는 곳을 알려 주시면 가장 도움이 됩니다.**

## 오프라인 설치

릴리스 asset 에는 `muni:v0.18.0` Docker 이미지가 포함되어 있습니다.

```bash
gzip -dc muni-v0.18.0.tar.gz | docker load
docker image inspect muni:v0.18.0

cp .env.example .env
# .env의 네 값을 운영 환경에 맞게 변경합니다.
docker compose -f compose.example.yaml --env-file .env up -d
```

애플리케이션이 반드시 필요로 하는 런타임 환경변수는 다음 네 개입니다.

| 환경변수                   | 설명                                 |
| -------------------------- | ------------------------------------ |
| `POSTGRES_DSN`             | PostgreSQL 접속 문자열               |
| `BOOTSTRAP_ADMIN`          | 최초 관리자 아이디 또는 이메일       |
| `BOOTSTRAP_ADMIN_PASSWORD` | 최초 관리자 비밀번호(12자 이상)      |
| `ENCRYPTION_KEY`           | base64로 인코딩한 32-byte master key |

PDF 변환 동작만 조정하는 선택 환경변수가 두 개 있습니다.

| 환경변수               | 기본값    | 설명                                       |
| ---------------------- | --------- | ------------------------------------------ |
| `MUNI_CHROMIUM_PATH`   | 자동 탐색 | PDF Export에 사용할 headless 브라우저 경로 |
| `MUNI_PDF_CONCURRENCY` | `2`       | 동시에 실행할 Chromium 프로세스 수(1~32)   |

## 운영 정보

- 서비스 포트: `8080`
- Liveness: `/healthz`
- Readiness: `/readyz`
- REST API: `/api/v1`
- 공개 링크: `/s/{token}` — 인증 없이 열리는 유일한 화면입니다
- OpenAPI: `/api/openapi.yaml` — 실제 라우트와 일치하며, 테스트가 그것을 지킵니다
- Prometheus: `/metrics` — 관리자 인증 필요
- MCP: `/mcp`
- 지원 DB: PostgreSQL 15 이상
- 이미지에는 PDF Export용 Chromium과 Noto CJK 글꼴이 포함되어 있습니다.
