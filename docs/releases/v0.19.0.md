muni 가 한글 문서를 **내보냅니다.** 지금까지는 읽기만 했습니다 — 한국 사무실이 muni 로 만든 문서를 밖으로 보낼 때 받는 쪽은 워드만큼이나 한글로 열기 때문에, 결국 `.hwpx` 여야 하는 경우가 많습니다.

## 추가

### 한글 문서 내보내기 (.hwpx)

쓰는 방식은 읽는 방식과 같습니다. 글은 `Contents/section0.xml` 에, 그것이 번호로 가리키는 서식은 `Contents/header.xml` 에, 그림은 `BinData` 에. 런은 저마다 charPr 번호를, 문단은 paraPr 번호를 부르므로 **문서가 쓰는 서로 다른 모양들을 모아 번호를 매깁니다** — HWPX 에는 서식을 붙은 자리에 적을 곳이 없습니다.

| 나가는 것 | 어떻게 |
| --- | --- |
| 제목 단계 | 한글이 부르는 이름 그대로 `개요 1~6` 스타일 |
| 굵게·기울임·밑줄·취소선·색·글꼴·크기 | charPr |
| 정렬·들여쓰기·첫 줄·줄간격 | paraPr |
| 표 | 가로·세로 병합, 머리글 행, 칸 세로 정렬 |
| 그림 | `BinData` 에 넣고 `<hc:img>` 로 가리킴 |
| 각주 | `<hp:footNote>` — 참조 안에 주석의 문단이 들어 있는 한글의 방식 그대로 |
| 목록 | 들여쓴 문단과 기호. 한글의 진짜 번호 매기기는 머리에 정의를 두고 목록마다 가리키는 방식이라, 글 안의 기호가 어느 화면에서나 같게 읽히고 왕복도 견딥니다 |
| 쪽 나누기·용지 방향 | `pageBreak`, `pagePr landscape` |

DOCX·PDF 와 달리 **정책 토글 뒤에 있지 않습니다.** HTML 내보내기만큼의 비용이고 Chromium 이 들어 있지 않습니다.

#### 쓰기가 읽기의 시험이었습니다

muni 가 `.hwpx` 를 쓰지 못하던 동안 읽기 테스트는 전부 **손으로 만든 파일**이었습니다. 그것은 읽는 쪽이 손과 일치한다는 것만 증명합니다. 쓰기가 생기자 **첫 왕복에서 읽기의 결함 둘이 바로 드러났습니다.**

- **각주를 읽지 않았습니다.** `<hp:footNote>` 를 본 적이 없어서, 실제 한글 파일의 각주가 가져올 때 전부 사라지고 있었습니다.
- **첫 줄 들여쓰기의 철자.** 형식은 그것을 `hc:intent` 라고 씁니다 — 한컴 자신의 철자이고 형식이 생긴 이래 그대로입니다. muni 는 `indent` 를 찾았고, 실제 파일 어디에도 없었습니다. 그것을 숨긴 시험 파일은 형식이 아니라 읽는 쪽을 보고 만들어져 있었습니다 — **이번 세션에서 세 번째입니다.**

둘 다 고쳤습니다. 이제 공유 커버리지 문서(`every-node.json`)가 쓰기 → 읽기를 통과하며 모든 구절, 낱말에 붙은 표시, 제목·표의 모양, 문단 배치, 그림을 확인합니다.

### 편집기: 표 칸 세로 정렬, 슬래시 메뉴의 도형

가져오기·내보내기는 되는데 **편집기에서 만들 수 없던** 두 가지입니다.

- **표 칸 세로 정렬.** 워드·한글 파일에서 읽어 오고 다시 써 주면서도 정할 방법이 없었습니다. 칸 음영 옆에 버튼 셋(위·가운데·아래)을 두었습니다.
- **도형 (mermaid).** 코드 블록 언어를 `mermaid` 로 직접 적어야 했습니다 — 도형 하나 그리려고 알아야 할 것이 아닙니다. 슬래시 메뉴에 「도형 (mermaid)」 항목이 생겼고, 빈 블록이 아니라 작은 순서도로 시작합니다.

## 미룬 것

**첫 페이지 다른 머리글.** 작다고 말씀드렸는데 아닙니다 — 데이터베이스 열과 마이그레이션, `.docx` 의 `titlePg` 와 머리글 파트 하나 더, PDF 의 `@page :first` 가 필요합니다. 반만 하느니 빼는 쪽을 택했습니다.

**워드 변경 추적 ↔ muni 제안.** 데이터 모델은 이미 있지만, 가져온 변경을 **누구 이름으로** 넣을지가 먼저입니다. 결정을 받고 하겠습니다.

## 아직 확인되지 않은 것

**두 한글 리더와 이 쓰기는 여전히 진짜 한글 파일로 확인되지 않았습니다.** 왕복 테스트는 muni 가 muni 와 일치한다는 것을 증명합니다 — 손으로 만든 파일보다 훨씬 낫고, 실제로 결함 둘을 찾았지만, 한글 오피스가 저장한 문서를 통과시켜 본 것과는 다릅니다. **`.hwpx` 를 내보내 한글에서 열어 보시고, 가지고 계신 `.hwp`·`.hwpx` 를 가져와 보시면 가장 도움이 됩니다.**

## 업그레이드

마이그레이션과 설정 변경은 필요하지 않습니다.

```bash
gzip -dc muni-v0.19.0.tar.gz | docker load
docker compose -f compose.example.yaml --env-file .env up -d
```

**v0.18.x 에서 `.hwpx` 를 가져오셨다면** 각주가 빠져 있을 수 있습니다. 그 손실은 가져오던 시점에 일어났으므로 되돌아오지 않습니다. 원본이 남아 있다면 다시 가져오면 이번에는 들어옵니다.

## 오프라인 설치

릴리스 asset 에는 `muni:v0.19.0` Docker 이미지가 포함되어 있습니다.

```bash
gzip -dc muni-v0.19.0.tar.gz | docker load
docker image inspect muni:v0.19.0

cp .env.example .env
# .env의 네 값을 운영 환경에 맞게 변경합니다.
docker compose -f compose.example.yaml --env-file .env up -d
```

애플리케이션이 반드시 필요로 하는 런타임 환경변수는 다음 네 개입니다.

| 환경변수                   | 설명                                 |
| -------------------------- | ------------------------------------ |
| `POSTGRES_DSN`             | PostgreSQL 접속 문자열               |
| `BOOTSTRAP_ADMIN`          | 최초 관리자 아이디 또는 이메일       |
| `BOOTSTRAP_ADMIN_PASSWORD` | 최초 관리자 비밀번호(12자 이상)      |
| `ENCRYPTION_KEY`           | base64로 인코딩한 32-byte master key |

PDF 변환 동작만 조정하는 선택 환경변수가 두 개 있습니다.

| 환경변수               | 기본값    | 설명                                       |
| ---------------------- | --------- | ------------------------------------------ |
| `MUNI_CHROMIUM_PATH`   | 자동 탐색 | PDF Export에 사용할 headless 브라우저 경로 |
| `MUNI_PDF_CONCURRENCY` | `2`       | 동시에 실행할 Chromium 프로세스 수(1~32)   |

## 운영 정보

- 서비스 포트: `8080`
- Liveness: `/healthz`
- Readiness: `/readyz`
- REST API: `/api/v1`
- 공개 링크: `/s/{token}` — 인증 없이 열리는 유일한 화면입니다
- OpenAPI: `/api/openapi.yaml` — 실제 라우트와 일치하며, 테스트가 그것을 지킵니다
- Prometheus: `/metrics` — 관리자 인증 필요
- MCP: `/mcp`
- 지원 DB: PostgreSQL 15 이상
- 이미지에는 PDF Export용 Chromium과 Noto CJK 글꼴이 포함되어 있습니다.
