발표자료 연동의 편집 링크 오류를 고치고, 한국어 보고서가 늘 요구하는 제목 번호 매기기와 표 셀 배경색을 넣었습니다.

## 수정

### 'Ptium에서 편집'이 없는 페이지로 가던 문제

발표자료 목록에서 **Ptium에서 편집**을 누르면 not-found 페이지가 열렸습니다.

muni는 `/presentations/{id}` 주소를 만들고 있었는데, Ptium의 라우터는 정확히 `/presentations/{id}/editor` 만 매치하고 **덱 단독 경로에 대한 라우트가 없습니다.** 링크가 도착할 곳이 아예 없었던 셈입니다.

```
/^\/presentations\/([^/]+)\/editor$/
```

주소 끝에 `/editor`를 붙이도록 고쳤습니다. 함께, 다른 시스템에서 받아온 presentation ID를 경로에 이스케이프 없이 이어붙이고 있던 것도 바로잡았습니다.

REST API 경로는 Ptium의 `openapi.yaml`과 대조해 확인했습니다. 잘못된 것은 웹 링크 하나뿐이었습니다.

## 추가

### 제목 번호 매기기

문서 개요 패널에서 번호 방식을 고르면 제목에 번호가 따라붙습니다.

| 방식 | 모양 |
| --- | --- |
| 번호 없음 | 기본값 |
| `1. 1.1. 1.1.1.` | 십진 |
| `I. 1. 가. 1)` | 한국 보고서 서식 |

절 하나를 끼워 넣으면 아래가 전부 다시 매겨집니다. 손으로 하면 아무도 제대로 유지하지 못하는 종류의 일입니다.

**번호는 저장하지 않습니다.** 편집기에서는 제목 앞에 그려 넣기만 하므로

- 문서에는 작성자가 실제로 쓴 글자만 남습니다. 복사해도 번호가 딸려오지 않습니다.
- 다른 사람이 번호 방식을 바꿔도, 아래 제목 전부를 고치는 편집으로 도착하지 않습니다.

내보낼 때는 서버가 사본에 한 번 써 넣습니다. 그래서 HTML·PDF·DOCX·Markdown·텍스트가 모두 같은 번호를 쓰고, 문서 안 목차도 그 번호를 그대로 가져갑니다.

편집기와 서버 양쪽이 **문서에 실제로 쓰인 가장 얕은 제목**을 기준으로 깊이를 셉니다. `제목 2`와 `제목 3`으로만 쓴 문서도 위에서부터 번호가 매겨지고, 화면과 내보낸 파일이 "2.1이 어느 절인지"를 두고 어긋나지 않습니다.

### 표 셀 배경색

표에서 구분할 수 있는 건 헤더 행뿐이어서, 합계 줄이나 구획을 말로 표시해야 했습니다. 이제 셀에 다섯 가지 색을 지정할 수 있습니다. 모두 검은 글씨 아래에서 인쇄해도 읽히는 톤입니다.

색은 HTML·PDF·DOCX로 나가고, Word 파일에서 가져올 때도 유지됩니다. 그전에는 어느 행이 헤더인지 판별하는 힌트로만 쓰고 버렸습니다.

이 작업에서 **따로 고칠 값어치가 있는 결함**이 나왔습니다. 색이 지정된 헤더 셀은 `w:shd` 요소를 두 번 쓰고 있었습니다. `CT_TcPr`은 하나만 허용하고, Word는 남는 것을 무시하는 대신 **파일을 통째로 거부합니다.** 작성자가 지정한 색이 헤더 기본값을 덮도록 바꿨습니다.

### 붙여넣기

- 주소를 선택한 글자 위에 붙여넣으면 그 글자가 **링크가 됩니다.** 글자가 주소로 바뀌지 않습니다.
- `Ctrl+Shift+V`는 서식 없이 붙여넣습니다. 다른 곳에서 복사한 스타일이 따라 들어오지 않습니다.

클립보드 전체가 `http`·`https`·`mailto` 주소일 때만 링크로 처리합니다. 주소를 언급한 문단은 그냥 글로 들어가고, 코드를 실행시키는 스킴은 링크가 되지 않습니다.

## 업그레이드

데이터베이스 마이그레이션이 하나 추가됩니다(`006_heading_numbering.sql`). 서버가 시작할 때 자동으로 적용되며, `documents` 표에 열 하나를 기본값 `'none'`으로 추가할 뿐 기존 데이터를 바꾸지 않습니다.

```bash
gzip -dc muni-v0.7.0.tar.gz | docker load
docker compose -f compose.example.yaml --env-file .env up -d
```

기존 문서는 번호 없음으로 열립니다.

발표자료 연동을 쓰고 계시면, 이번 교체만으로 편집 링크가 정상 동작합니다. 설정을 다시 입력할 필요는 없습니다.

## 오프라인 설치

릴리스 asset에는 `muni:v0.7.0` Docker 이미지가 포함되어 있습니다.

```bash
gzip -dc muni-v0.7.0.tar.gz | docker load
docker image inspect muni:v0.7.0

cp .env.example .env
# .env의 네 값을 운영 환경에 맞게 변경합니다.
docker compose -f compose.example.yaml --env-file .env up -d
```

애플리케이션이 반드시 필요로 하는 런타임 환경변수는 다음 네 개입니다.

| 환경변수                   | 설명                                 |
| -------------------------- | ------------------------------------ |
| `POSTGRES_DSN`             | PostgreSQL 접속 문자열               |
| `BOOTSTRAP_ADMIN`          | 최초 관리자 아이디 또는 이메일       |
| `BOOTSTRAP_ADMIN_PASSWORD` | 최초 관리자 비밀번호(12자 이상)      |
| `ENCRYPTION_KEY`           | base64로 인코딩한 32-byte master key |

PDF 변환 동작만 조정하는 선택 환경변수가 두 개 있습니다.

| 환경변수               | 기본값    | 설명                                       |
| ---------------------- | --------- | ------------------------------------------ |
| `MUNI_CHROMIUM_PATH`   | 자동 탐색 | PDF Export에 사용할 headless 브라우저 경로 |
| `MUNI_PDF_CONCURRENCY` | `2`       | 동시에 실행할 Chromium 프로세스 수(1~32)   |

## 운영 정보

- 서비스 포트: `8080`
- Liveness: `/healthz`
- Readiness: `/readyz`
- REST API: `/api/v1`
- OpenAPI: `/api/openapi.yaml`
- MCP: `/mcp`
- 지원 DB: PostgreSQL 15 이상
- 이미지에는 PDF Export용 Chromium과 Noto CJK 글꼴이 포함되어 있습니다.
