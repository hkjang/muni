문서와 발표자료를 연결하고, AI가 문서를 읽고 고칠 것을 제안하며, 버전 사이의 변경을 블록 단위로 비교하는 릴리스입니다. 공동편집 이력이 무한히 쌓이던 문제도 함께 해결했습니다.

## 발표자료 만들기 (Ptium 연동)

muni는 발표자료 엔진을 직접 두지 않고 [Ptium](https://github.com/hkjang/ptium)에 REST로 요청합니다. muni는 문서·협업·승인·버전을, Ptium은 스토리라인 설계·슬라이드 생성·디자인·Export를 맡습니다.

- 편집기 내보내기 메뉴의 **발표자료 만들기**에서 대상·목적·발표 시간·상세 수준을 고르면 그 값으로 슬라이드 수를 추천합니다. 40쪽 문서를 40장으로 만들지 않기 위해서입니다.
- 문서를 평문으로 눌러 넘기지 않고 **ProseMirror 구조를 그대로 읽어** 중간 모델(Presentation Brief)로 옮깁니다. 번호 목록은 단계로, 날짜가 붙은 목록은 타임라인으로, 수치가 든 항목은 지표로, 표는 표로 전달되어 Ptium이 KPI·프로세스·타임라인 컴포넌트를 고를 수 있습니다.
- 만들어진 자료는 편집기 오른쪽 **발표자료** 탭에서 상태·슬라이드 수와 함께 보이고, Ptium 편집기로 바로 이동하거나 PPTX를 받을 수 있습니다.
- muni는 연결 정보만 보관합니다. 슬라이드와 파일은 Ptium에 있고, 사본을 두면 Ptium에서 편집하는 순간 두 시스템이 어긋납니다.

### 변경된 슬라이드만 동기화

발표자료를 만든 뒤 문서를 고쳤다면 **변경 반영**으로 어떤 슬라이드가 영향을 받는지 먼저 봅니다. 문서 diff를 블록 단위로 계산해 각 블록이 속한 제목을 찾고, 그 제목에 해당하는 슬라이드만 `유지 / 다시 작성 / 추가 필요 / 삭제 후보`로 알려 줍니다.

실행하면 **바뀐 슬라이드만** 다시 작성하고 나머지는 원문 그대로 되돌려 놓습니다. Ptium 편집기에서 손본 레이아웃·문구·발표 메모가 살아남습니다. 전체를 다시 생성하면 그 작업이 전부 사라집니다.

쓰기 직전에 발표자료 버전을 읽어 넘기므로, 그사이 Ptium에서 누군가 편집했다면 덮어쓰지 않고 재시도 안내와 함께 거절합니다.

### 출처 표시

각 슬라이드에 근거가 된 문서와 버전, 해당 항목을 적어 넣습니다(`AI전략보고서 (Revision 23) | 추진 현황`). 표지와 마무리 슬라이드는 건너뛰고, 이미 출처가 적힌 슬라이드는 손대지 않습니다.

## AI

### 문서 Agent가 도구를 씁니다

`tools: true`로 요청하면 모델이 문서 검색, 문서 읽기, 목차 확인, 버전 목록, 버전 비교를 스스로 호출한 뒤 답합니다. 편집기 Agent 패널에서 **워크스페이스 문서까지 찾아보기**를 켜면 사용할 수 있고, 어떤 도구를 거쳤는지 진행 중에 표시됩니다.

모든 도구는 **요청한 사용자의 문서 ACL을 그대로 적용**하므로 그 사람이 볼 수 없는 문서에는 닿지 않고, 호출 하나하나가 감사 로그에 남습니다. 도구는 읽기만 합니다.

### 선택 영역 AI 메뉴

문장을 드래그해 선택하면 다듬기·짧게·자세히·맞춤법·격식체·요약·목록으로·영어로와 직접 지시를 실행할 수 있습니다. 결과는 미리보기로 먼저 보여 주고 **적용**을 눌러야 반영됩니다.

### 문서 전체 변경 제안

AI에게 문서를 검토해 고칠 부분을 제안하도록 요청할 수 있습니다. 결과는 동료가 남긴 것과 같은 **변경 제안 목록**에 들어가며, 각 제안은 위치가 아니라 블록에 고정됩니다. 검토 중 문서가 바뀌어도 엉뚱한 곳을 가리키지 않고, 대상 블록이 사라졌다면 적용을 거부합니다.

### AI API 호환성

게이트웨이가 `tools`를 거절하면 도구 없이 일반 답변으로 물러납니다. 기존의 `max_tokens`·`stream_options`·`temperature`·역할 이름 보정도 그대로 동작합니다.

## 버전 비교

버전 기록 패널에서 두 버전을 선택하면 블록 단위로 무엇이 바뀌었는지 비교합니다.

- 블록마다 붙은 **안정적인 ID**로 짝을 맞추기 때문에 위에 문단을 하나 넣었다고 그 아래가 전부 바뀐 것으로 보이지 않습니다.
- 추가·삭제·변경·이동이 구분되고, 변경된 블록은 단어 단위(한글은 글자 단위)로 어디가 달라졌는지 표시합니다.
- 변경되지 않은 블록은 나열하지 않고 개수만 알려 줍니다.
- 같은 결과를 `GET /api/v1/documents/{id}/revisions/{from}/diff/{to}`로도 받을 수 있습니다.

## 블록 정체성

문단·제목·인용·코드 블록·구분선·이미지·목록 항목·체크 항목·표에 안정적인 `blockId`가 붙습니다. 댓글·인용·AI 제안·버전 비교·딥링크가 모두 위치가 아닌 블록을 가리킬 수 있습니다.

편집기는 분할과 붙여넣기가 원본의 속성을 복사한다는 점을 고려해 트랜잭션 단계에서 식별자를 부여하므로, 두 블록이 같은 정체성을 주장하는 일이 없습니다. 가져오기로 들어온 문서는 서버가 부여하고, HTML 내보내기는 `data-block-id`로 기록해 다시 가져와도 앵커가 살아남습니다.

## 공동편집 이력 압축

Yjs update가 append-only로 쌓이고, 문서를 열 때마다 클라이언트가 전체 상태를 다시 append하고 있었습니다. 이력이 편집량뿐 아니라 **열어본 횟수에도 비례해** 늘었습니다.

- 누적된 update가 임계값(400건 또는 4MiB)을 넘으면 서버가 접속 중인 편집자 한 명에게 압축을 요청하고, 돌려받은 병합 상태로 이전 update를 대체합니다.
- 접속 시 클라이언트는 서버가 갖지 않은 부분만 계산해 보냅니다. 오프라인 편집은 그대로 올라가고, 변경이 없으면 아무것도 보내지 않습니다.
- 버전 복원 시 스냅샷도 함께 정리됩니다.

## 업그레이드

데이터베이스 마이그레이션 두 개(`collab_snapshots`, `document_presentations`)와 `suggestions` 테이블 확장이 최초 기동 시 자동 적용됩니다. 설정 변경은 필요하지 않습니다.

발표자료 연동을 쓰려면 **서비스 관리 → 서비스 설정**에서 Ptium 주소와 API key를 입력하십시오. 설정하지 않으면 관련 메뉴가 나타나지 않고 나머지 기능은 그대로 동작합니다.

```bash
gzip -dc muni-v0.3.0.tar.gz | docker load
docker compose -f compose.example.yaml --env-file .env up -d
```

## 오프라인 설치

릴리스 asset에는 `muni:v0.3.0` Docker 이미지가 포함되어 있습니다.

```bash
gzip -dc muni-v0.3.0.tar.gz | docker load
docker image inspect muni:v0.3.0

cp .env.example .env
# .env의 네 값을 운영 환경에 맞게 변경합니다.
docker compose -f compose.example.yaml --env-file .env up -d
```

애플리케이션이 반드시 필요로 하는 런타임 환경변수는 다음 네 개입니다.

| 환경변수                   | 설명                                 |
| -------------------------- | ------------------------------------ |
| `POSTGRES_DSN`             | PostgreSQL 접속 문자열               |
| `BOOTSTRAP_ADMIN`          | 최초 관리자 아이디 또는 이메일       |
| `BOOTSTRAP_ADMIN_PASSWORD` | 최초 관리자 비밀번호(12자 이상)      |
| `ENCRYPTION_KEY`           | base64로 인코딩한 32-byte master key |

PDF 변환 동작만 조정하는 선택 환경변수가 두 개 있습니다.

| 환경변수               | 기본값    | 설명                                       |
| ---------------------- | --------- | ------------------------------------------ |
| `MUNI_CHROMIUM_PATH`   | 자동 탐색 | PDF Export에 사용할 headless 브라우저 경로 |
| `MUNI_PDF_CONCURRENCY` | `2`       | 동시에 실행할 Chromium 프로세스 수(1~32)   |
