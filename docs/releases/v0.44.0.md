muni 안에서만 쌓이던 알림을 **사내 SMTP 릴레이로 메일로 보냅니다** — 사람이 기다리고 있는 네 가지만, 한 사람에게는 한 통으로 묶어서, 시도마다 기록을 남기며. 기본은 꺼짐이라 켜기 전까지 아무것도 달라지지 않습니다.

## 추가

### 메일 알림 (서비스 설정 → 「메일 알림」)

검토를 기다리는 문서, 결재 결과, 댓글에서 나를 부른 것 — 사람이 알아야 할 일은 muni 안에서 알림으로 생겼지만, muni 를 열지 않으면 닿지 않았습니다. 사내 서비스 표준(MAIL-STANDARD)대로 그 알림을 **사내 SMTP 릴레이**로 보냅니다. 릴레이 주소로 사내 메일 서비스를 가리키면 알림이 건물 밖으로 나가지 않습니다.

설정 키를 표준의 이름(`mail.enabled`, `mail.smtp_host`, `mail.security`, …)으로 옮기고 기본값을 사내 릴레이의 흔한 모양으로 두었습니다 — **25번 포트, 인증 없음, 보안 방식은 `auto`**. `auto` 는 릴레이가 STARTTLS 를 알리면 올리고 알리지 않으면 그대로 보냅니다. 사내 릴레이는 대개 아무도 문서로 남기지 않은 것이라, 운영자가 먼저 알아내야만 첫 통이 나가는 일이 없도록 한 기본값입니다. `none`·`starttls`·`tls` 로 못 박을 수 있고 465 포트는 `tls` 로 봅니다. 계정 정보는 **암호화된 연결로만** 보냅니다 — 릴레이가 TLS 를 주지 않으면 계정을 비워야 하고, 그렇지 않으면 보내는 대신 거절합니다.

**보내는 것은 넷뿐입니다.** 이 메일이 오지 않으면 누군가 손해를 보거나 화면을 계속 새로 고치게 되는 것만 보냅니다 — 검토·결재 요청(내 차례), 검토 결과, 댓글 멘션, 그리고 **API 키 만료 임박**(새로 씁니다. 7일 안에 만료되면 키마다 한 번). 이벤트마다 `mail.notify_*` 스위치가 따로 있습니다. 「무언가 바뀜」은 보내지 않습니다 — 첫 주에 너무 많이 오면 사람들은 규칙을 만들어 통째로 버리고, 그러면 정말 필요한 알림도 함께 버려집니다.

같은 이유로 한 사람에게 쌓인 알림은 **한 통으로 묶습니다.** 댓글 하나에서 두 번 불렸거나 같은 1분 안에 여럿이 생겨도 메일은 하나이고, 제목은 「[muni] 첫 제목 외 N건」, 본문에 생긴 순서대로 적힙니다. 자기가 한 일은 자기에게 가지 않고, 받는 주소는 계정의 이메일이라 이메일이 없거나 비활성인 계정에는 가지 않습니다. **문서 내용은 담지 않습니다** — 알림 메일이 문서를 실어 나르면 받는 사람이 메일을 어디로 전달하든 그 내용도 함께 갑니다.

**요청을 막지 않습니다.** 메일은 1분마다 배경에서 한 번 나갑니다. 릴레이가 느리거나 죽어 있어도 댓글을 다는 일, 결재를 올리는 일은 평소처럼 끝나고, 실패한 알림은 하루 동안 세 번까지 다시 시도한 뒤 놓습니다. 시도 횟수는 보내기 **전에** 올립니다 — 반복해서 실패하는 주소를 1분마다 영원히 다시 부르지 않기 위해서입니다.

### 발송 기록과 시험 발송

메일은 보낸 뒤 확인할 방법이 없으면 「안 왔다」는 문의에 답할 수 없습니다. 건물 밖으로 나가려 한 메일이 **시도마다 한 줄씩** `mail_deliveries` 에 남습니다 — 언제, 어떤 이벤트로, 누구에게, 제목이 무엇이었고, 되었는지 안 되었는지. 성공도 남기고 **본문은 담지 않습니다**. 본문까지 담으면 이 표가 그 자체로 유출 경로가 됩니다. 관리 화면의 같은 탭에서 보고, `GET /api/v1/admin/mail/deliveries` 로도 읽습니다(`status=sent|failed` 로 거르고 `limit` 으로 자릅니다). 보존 기간은 「보존 정책」의 감사 로그와 같고, 미리보기의 건수에도 함께 셉니다.

「내 주소로 시험 메일 보내기」는 **지금 폼에 적힌 값으로** 관리자 자신의 주소에 실제 한 통을 보내고 결과를 그 자리에 보여 줍니다. 저장하기 전에 릴레이를 확인할 수 있고, 비밀번호를 비워 두면 저장된 것을 씁니다. 거의 맞은 메일 설정은 맞은 것과 똑같이 생겼으므로, 아는 방법은 한 통 보내 보는 것뿐입니다. 실패 문구는 릴레이의 답 그대로입니다.

[관리자 가이드](https://github.com/hkjang/muni/blob/v0.44.0/docs/ADMIN_GUIDE.md#메일-알림)에 설정 표와 보내는 것·보내지 않는 것, 「메일이 안 왔다」 대응을 더했습니다.

## 그 밖에

시험 발송 경로의 이름이 설정 키를 따라 바뀌었습니다 — `POST /api/v1/admin/settings/test-smtp` 가 **`POST /api/v1/admin/settings/test-mail`** 입니다. 화면은 새 경로를 쓰므로 관리자가 할 일은 없고, 이 경로를 직접 부르던 스크립트가 있다면 주소만 고치면 됩니다. 발송 기록 경로와 함께 OpenAPI(`/api/openapi.yaml`)에 적었습니다.

관리 설정 화면에서 메일 부분을 `MailSettings` 로 떼어냈습니다. 스위치·시험 발송·발송 기록이 한 탭에 모여 있고, 화면의 다른 탭은 그대로입니다.

## 업그레이드

마이그레이션이 하나 있습니다(`019`). 기동할 때 자동으로 적용되며 세 가지를 합니다 — 옛 `smtp.*` 설정 행을 **이름만** `mail.*` 로 바꾸고, 발송 기록 표 `mail_deliveries` 를 만들고, API 키 알림이 같은 키를 두 번 보내지 않도록 `notifications` 에 인덱스를 더합니다. 값은 그대로이므로 릴레이 주소·포트·발신 주소를 다시 적을 필요가 없습니다.

**비밀번호는 다시 입력하지 않아도 됩니다.** `smtp.password` 는 봉인할 때 키 이름을 함께 묶어 두어 이름을 바꾸면 열리지 않으므로 옮기지 않았습니다. 코드가 새 이름을 먼저 보고 없으면 옛 이름을 읽으며, 관리자가 비밀번호를 새로 저장하는 그때 새 이름으로 적힙니다.

**메일을 이미 켜 둔 곳이라면** 나가는 메일이 달라집니다. 전에는 알림 하나에 메일 한 통이 종류를 가리지 않고 나갔지만, 이제 위의 네 가지만 나가고 한 사람 몫은 한 통으로 묶입니다. API 키 만료 알림은 새로 생긴 것이라, 7일 안에 만료되는 키를 가진 사람에게 한 번 갑니다. 각 이벤트 스위치는 켜진 채로 올라오므로 필요 없는 것은 「메일 알림」 탭에서 끕니다. **메일을 켜 두지 않은 곳은 아무것도 달라지지 않습니다** — 새 설치는 꺼진 채로 올라오고, 켜도 릴레이 주소와 보내는 주소가 없으면 보내지 않습니다.

```bash
gzip -dc muni-v0.44.0.tar.gz | docker load
docker compose -f compose.example.yaml --env-file .env up -d
```

| `BOOTSTRAP_ADMIN_PASSWORD` | 최초 관리자 비밀번호(12자 이상)      |
| `ENCRYPTION_KEY`           | base64로 인코딩한 32-byte master key |

## 운영 정보

- 서비스 포트: `8080`
- Liveness: `/healthz`
- Readiness: `/readyz`
- REST API: `/api/v1`
- 공개 링크: `/s/{token}` — 인증 없이 열리는 유일한 화면입니다
- 문서 넘기기: `/handoff?source&claim` (받는 쪽, 세션 필요, 허용 목록의 오리진만) · `/api/v1/handoff/claims/{claim}` (내주는 쪽, 인증 없이 5분짜리 단일 사용 표로만 열립니다)
- 메일 알림: 사내 SMTP 릴레이로 1분마다 배경 발송, 기본 꺼짐 · 발송 기록 `/api/v1/admin/mail/deliveries` (관리자 인증 필요)
- OpenAPI: `/api/openapi.yaml` — 실제 라우트와 일치하며, 테스트가 그것을 지킵니다
- Prometheus: `/metrics` — 관리자 인증 필요
- MCP: `/mcp`
- Momento 프록시: `/momento/*` — 방문 추적을 Momento 로 켜 둔 동안에만 답합니다
- 지원 DB: PostgreSQL 15 이상
- 이미지에는 PDF Export용 Chromium과 Noto CJK 글꼴이 포함되어 있습니다.
