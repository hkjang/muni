워드 문서를 muni에서 열었을 때 사라지던 것들을 찾아 메웠습니다. 머리글의 「대외비」, 줄 간격과 첫 줄 들여쓰기, 그리고 가로 인쇄. 여기에 화면 낭독기로 편집기를 쓸 수 있게 하는 작업과, 처음 받는 파일 크기를 3분의 1로 줄이는 작업이 함께 들어갑니다.

## 워드 대비

무엇이 부족한지는 짐작하지 않고, 한국 공문서 형태의 워드 문서를 만들어 넣어 보고 무엇이 사라지는지 셌습니다. **가져오기 자체는 좋았습니다** — 굵게·기울임·글자색·양쪽 정렬·글머리 기호·번호 목록·표(셀 병합 포함)·페이지 나누기가 모두 살아남습니다. 사라지는 것은 셋이었습니다.

### 머리글과 바닥글이 통째로 사라지고 있었습니다

한국 공문서는 분류 표시를 본문이 아니라 **페이지 위**에 답니다 — 대외비, 부서명, 문서번호. muni는 `.docx`의 머리글·바닥글 파트를 아예 읽지 않았고, 읽지 않는다는 말도 하지 않았습니다. **대외비가 붙은 문서를 가져오면 그 글자가 사라진 채 들어왔습니다.** 서식 손실이 아니라 뜻의 손실입니다.

이제 문서마다 한 줄씩 가지고, `더 보기 → 페이지 설정`에서 인쇄 미리보기와 함께 편집합니다.

- **가져오기**: `sectPr`의 기본 머리글·바닥글을 읽습니다. 워드는 섹션마다 세 개(첫 페이지·짝수·홀수)를 가질 수 있지만 muni는 하나이므로 모든 페이지에 나오는 기본값을 가져옵니다. 첫 페이지용을 매 페이지에 찍으면 다른 문서가 됩니다.
- **내보내기(.docx)**: `header1.xml`·`footer1.xml`을 쓰고 `sectPr`에서 참조합니다. 참조 없는 파트나 파트 없는 참조는 워드가 손상됐다고 하는 파일이라, 둘은 함께 만들어지거나 둘 다 없습니다.
- **내보내기(PDF)**: 머리글 띠가 켜져 있으면서 비어 있었습니다 — 자리는 잡아먹고 아무것도 찍지 않았습니다.

머리글은 한 줄입니다. 붙여넣은 줄바꿈은 띄어쓰기로 접습니다 — 머리글의 줄바꿈은 두 번째 머리글이 아니라, 읽는 프로그램마다 다르게 그려지는 파일을 만듭니다.

### 가로 인쇄가 불가능했습니다

A4 세로가 코드 세 곳에 박혀 있었습니다. 한국 사무 문서는 넓은 표로 가득하고 그것을 가로로 인쇄하는 것은 워드에서 일상인데, muni에서는 방법이 없었습니다.

`페이지 설정`에서 세로/가로를 고르면 `.docx`·PDF·HTML 세 경로 모두에 적용되고, 워드 문서를 가져올 때 그 문서의 방향도 읽습니다.

**종이만 돌려서는 안 됩니다.** 페이지를 돌리는 이유는 넓어진 폭인데, 표의 열 너비와 그림의 최대 크기가 세로 기준 본문 폭에 맞춰져 있었습니다. 그대로 두면 넓어진 지면 가운데 좁은 표가 놓이고 양옆이 빕니다. 본문 폭을 방향에서 계산하도록 바꿔서 표가 가로 지면을 채웁니다.

**워드는 `w:orient`를 읽지, 가로가 세로보다 크다는 사실을 읽지 않습니다.** 크기만 바꾸면 모양은 맞는데 엉뚱한 용지에 인쇄되는 문서가 나옵니다.

## 수정

### muni가 자기가 쓴 서식을 다시 읽지 못했습니다

문단의 들여쓰기·첫 줄 들여쓰기·줄 간격을 `.docx`에 **정확히 기록하고 있었고, 읽을 때는 셋 다 버리고 있었습니다.** 문서에 서식을 잡고 워드로 내보낸 뒤 다시 열면 납작하게 돌아왔습니다. 워드에서 온 문서도 마찬가지였습니다 — 줄 간격 160%에 첫 줄 들여쓰기는 한국 공문서의 기본 서식인데 둘 다 사라졌습니다.

읽을 때 판단이 필요했던 곳들:

- **목록 항목의 들여쓰기는 작성자가 정한 것이 아닙니다.** 목록 자체의 들여쓰기가 같은 속성으로 표현되므로, 그것을 작성자 설정으로 읽으면 파일이 한 번 오갈 때마다 모든 글머리가 한 단계씩 더 밀려납니다.
- **들여쓰기는 내림이 아니라 반올림합니다.** 워드 문서는 작성자가 눈금자를 끌어다 놓은 값을 쓰므로 430 twips 같은 값이 나옵니다. 그것은 0단계가 아니라 1단계입니다.
- **고정 줄 간격은 건너뜁니다.** `w:lineRule`이 `exact`이면 `w:line`은 배수가 아니라 twips 단위 높이입니다. 배수로 읽으면 20pt가 1.67배가 됩니다.
- **지정하지 않은 문단의 줄 간격은 값 없이 돌려줍니다.** 워드는 아무도 정하지 않은 문단에도 `w:line`을 쓰므로, 그대로 읽으면 편집기의 줄 간격 칸이 작성자가 고른 적 없는 숫자로 채워집니다.

### 권한이 없어 거부된 요청이 성공했다고 답하고 있었습니다

*(v0.14.0에서 고쳤으나 그 릴리스 노트에 함께 적었습니다. 여기서는 반복하지 않습니다.)*

## 접근성

아이콘만 있는 버튼에 이름이 없으면 화면 낭독기는 "버튼"이라고만 읽습니다. **편집기 툴바는 거의 전부가 아이콘 버튼이라, 그 상태로는 낭독기로 편집이 불가능했습니다.** 국내 공공·기업 조달이 명시적으로 요구하는 항목이기도 합니다(컨트롤의 명칭 제공).

원인은 구체적이었습니다. MUI의 툴팁은 버튼이 직접 자식일 때 이름을 붙여 주는데, 비활성 버튼 위에도 툴팁이 뜨게 하려고 사이에 `<span>`을 두면 라벨이 그 span에 붙고 버튼에는 아무것도 남지 않습니다. 추론이 아니라 실제 접근성 트리로 확인했습니다.

라벨 없는 버튼 16개를 고쳤고, 다시 생기지 않도록 검사를 테스트로 남겼습니다. 라벨을 하나 지워서 그 파일과 줄을 짚는지 확인했습니다 — 통과만 하고 아무것도 못 잡는 검사는 검사가 아닙니다.

## 성능

### 처음 받는 파일이 1.6MB였습니다

모든 화면이 한 파일에 들어 있었습니다. 로그인 화면이 비밀번호 입력란을 보여주기 전에 편집기와 관리자 화면 전부를 내려받았고, **공개 링크 페이지도 그랬습니다** — 계정도 없고 관리 화면을 받을 이유도 없는 조직 밖 사람에게 관리 인터페이스를 통째로 보내고 있었습니다.

| | 전 | 후 |
| --- | --- | --- |
| 처음 받는 양 | 1,627 kB (gzip 497 kB) | 484 kB (gzip 151 kB) |
| 로그인 화면의 편집기 | 포함 | 없음 |
| 공개 링크 페이지의 관리자 화면 | 포함 | 없음 |

화면이 별도 파일로 오면 네트워크가 끊긴 상태에서 그 화면으로 들어갈 때 실패합니다. 그래서 확인해 보니 **에러 바운더리가 아예 없었습니다** — 어느 컴포넌트든 렌더 중 예외를 던지면 트리 전체가 사라지고 사용자는 흰 화면을 봅니다. 바운더리를 넣으면서 화면 파일을 못 받은 경우를 따로 구분해 말합니다. 그 경우에는 새로고침이 진짜 해결책이고, 코드 버그일 때는 아니기 때문입니다.

### 외래 키 인덱스

외래 키 31개에 뒤를 받치는 인덱스가 없었습니다. 대부분은 상관없습니다. 사람 300명·워크스페이스 60개·문서 2만 건·첨부 6천 건에서 실제 실행 계획에 나타난 것만 골랐습니다.

| 질의 | 전 | 후 |
| --- | --- | --- |
| 문서의 첨부 목록 | 0.50ms (5,994행 훑음) | 0.073ms |
| 휴지통 문서 세기 | 2.7ms (20,055행 훑음) | 0.083ms |
| 문서 100건 삭제(연쇄) | 36.8ms | 18.7ms |
| 내 워크스페이스 목록 | Seq Scan | Bitmap Index Scan |

워크스페이스 목록은 매 페이지 로드마다 돕니다. 연쇄 삭제는 보존 정책이 대량으로 하는 일입니다.

## 업그레이드

마이그레이션이 세 개 있습니다(`014` 인덱스, `015` 머리글·바닥글, `016` 용지 방향). 기동할 때 자동으로 적용되고 설정 변경은 필요하지 않습니다.

`014`는 인덱스를 만듭니다. 마이그레이션 실행기가 파일마다 트랜잭션을 열기 때문에 `CONCURRENTLY`를 쓸 수 없어, 큰 데이터베이스에서는 빌드하는 동안 쓰기 잠금이 걸립니다. 몇 초이고, 어차피 재시작 중이라 이미 멈춰 있는 시간입니다.

```bash
gzip -dc muni-v0.15.0.tar.gz | docker load
docker compose -f compose.example.yaml --env-file .env up -d
```

## 오프라인 설치

릴리스 asset에는 `muni:v0.15.0` Docker 이미지가 포함되어 있습니다.

```bash
gzip -dc muni-v0.15.0.tar.gz | docker load
docker image inspect muni:v0.15.0

cp .env.example .env
# .env의 네 값을 운영 환경에 맞게 변경합니다.
docker compose -f compose.example.yaml --env-file .env up -d
```

애플리케이션이 반드시 필요로 하는 런타임 환경변수는 다음 네 개입니다.

| 환경변수                   | 설명                                 |
| -------------------------- | ------------------------------------ |
| `POSTGRES_DSN`             | PostgreSQL 접속 문자열               |
| `BOOTSTRAP_ADMIN`          | 최초 관리자 아이디 또는 이메일       |
| `BOOTSTRAP_ADMIN_PASSWORD` | 최초 관리자 비밀번호(12자 이상)      |
| `ENCRYPTION_KEY`           | base64로 인코딩한 32-byte master key |

PDF 변환 동작만 조정하는 선택 환경변수가 두 개 있습니다.

| 환경변수               | 기본값    | 설명                                       |
| ---------------------- | --------- | ------------------------------------------ |
| `MUNI_CHROMIUM_PATH`   | 자동 탐색 | PDF Export에 사용할 headless 브라우저 경로 |
| `MUNI_PDF_CONCURRENCY` | `2`       | 동시에 실행할 Chromium 프로세스 수(1~32)   |

## 운영 정보

- 서비스 포트: `8080`
- Liveness: `/healthz`
- Readiness: `/readyz`
- REST API: `/api/v1`
- 공개 링크: `/s/{token}` — 인증 없이 열리는 유일한 화면입니다
- OpenAPI: `/api/openapi.yaml` — 실제 라우트와 일치하며, 테스트가 그것을 지킵니다
- Prometheus: `/metrics` — 관리자 인증 필요
- MCP: `/mcp`
- 지원 DB: PostgreSQL 15 이상
- 이미지에는 PDF Export용 Chromium과 Noto CJK 글꼴이 포함되어 있습니다.
