반쯤 만들어진 채 남아 있던 기능들을 마무리하고, 한국어 검색과 결재를 실제로 쓸 수 있게 만든 릴리스입니다.

## 마무리한 것

이 릴리스의 상당 부분은 새 기능이 아니라, **데이터베이스에는 있는데 화면이나 API가 없던 것들**입니다.

### 알림함

알림은 처음부터 기록되고 있었고, 읽을 방법이 없었습니다. 조회 엔드포인트도 화면도 없어서, 검토 요청은 그 사람이 마침 해당 문서를 열어야만 닿았습니다. 지난 릴리스에서 메일을 붙이자 이 빈자리가 더 드러났습니다 — 메일함에서만 볼 수 있는 알림은 절반짜리입니다.

이제 상단에 종 아이콘과 읽지 않은 개수가 있고, 누르면 그 문서로 이동하며 읽음 처리됩니다. 이동 위치는 알림 메일의 링크와 **같은 정보로 계산**하므로, 앱에서 열든 메일에서 열든 같은 곳에 도착합니다.

### 서식

`templates` 테이블은 처음부터 있었고 **넣을 방법이 없었습니다.** 만드는 엔드포인트도 목록도 없었고, 새 문서가 받던 `templateId`는 **읽은 뒤 그냥 버려졌습니다.** '서식으로 만든 문서'가 빈 문서였다는 뜻입니다.

이제 서식을 만들고 이름을 바꾸고 지울 수 있으며, 워크스페이스는 자기 서식과 전사 공용 서식을 함께 봅니다. 새 문서가 실제로 그 서식에서 시작합니다. 서식은 보통 이미 쓴 문서에서 출발하므로, 편집 화면에서 **현재 문서를 서식으로 저장**할 수 있습니다.

서식은 참조가 아니라 복사입니다. 나중에 서식을 바꾸거나 지워도 이미 만든 문서는 그대로입니다.

### 태그

태그 테이블도 처음부터 있었고 **검색은 줄곧 태그를 뒤지고 있었습니다.** 아무도 달 수 없는 태그를요.

이제 문서에 태그를 달고, 문서 카드에서도 보이며, 워크스페이스의 기존 태그가 제안됩니다. 태그는 이름으로 지정합니다 — 이미 있는지는 muni가 알아서 판단합니다. 컬럼이 `citext`라 `Draft`와 `draft`는 한 태그이고, 두 사람이 동시에 같은 태그를 달아도 오류 없이 하나가 됩니다.

### 폴더와 문서 이동

폴더는 **문서를 만드는 순간에만** 고를 수 있었습니다. 나중에 옮길 방법이 없었고, 폴더 자체도 만들기와 목록뿐이었습니다.

이제 문서를 다른 폴더나 워크스페이스로 옮기고, 폴더 이름 변경·이동·삭제가 됩니다.

- 워크스페이스를 옮기면 문서를 볼 수 있는 사람이 달라지므로, 편집 방을 닫아 열어 두고 있던 사람이 새 권한으로 다시 연결됩니다.
- 폴더를 **자기 하위 폴더 안으로** 옮기면 그 가지가 트리에서 떨어져 나가 아무도 찾을 수 없게 됩니다. 조상 관계를 확인해 거부합니다.
- 폴더를 지워도 **안에 있던 문서와 하위 폴더는 지워지지 않고 상위로 올라갑니다.** 폴더를 정리하는 사람이 문서를 없애달라고 한 것은 아니기 때문입니다.

폴더 선택 목록은 이름이 아니라 경로를 보여줍니다. `2025 / 상반기`와 `2026 / 상반기`는 이름만으로 구분되지 않습니다.

## 추가

### 결재선

한국의 보고서는 순서대로 결재됩니다 — 팀장, 부서장, 본부장. 그리고 **자기 차례인 사람만** 결재할 수 있습니다. muni는 '관리자 중 아무나 N명'만 표현할 수 있었는데, 그것은 다른 방식이고 결재선을 쓰는 조직이 원하는 것이 아닙니다.

검토 요청 시 결재선을 지정할 수 있습니다.

- 지금 차례인 사람만 결재합니다. 결재 권한이 **역할이 아니라 결재선에서** 나오므로, 관리자가 아닌 사람도 결재선에 설 수 있습니다.
- 승인하면 다음 사람에게만 알립니다. 전원에게 한 번에 알리면 줄서기가 아니라 뒤엉킴이 됩니다.
- 반려하면 거기서 끝나고, 뒤 차례는 '건너뜀'으로 표시됩니다. 오지 않을 차례를 기다리게 두지 않습니다.
- **전결**로 표시한 단계에서 승인되면 뒤 차례를 건너뜁니다.

결재선의 문제는 요청이 만들어지기 **전에** 걸러집니다 — 문서를 볼 수 없는 사람, 같은 사람이 두 번, 정책이 금지하는데 본인이 들어간 경우. 3단계에서 알게 되는 것은 너무 늦습니다.

기존 방식은 그대로 두었고 기본값입니다.

### 검색 필터

검색창 하나가 전부였습니다. 워크스페이스·작성자·태그·기간으로 거를 수 있습니다. **키워드 없이 필터만으로도** 검색됩니다 — "지난달에 내가 여기 쓴 것 전부"에는 검색어가 없습니다. 조건은 주소에 담기므로 공유하거나 북마크할 수 있습니다.

### 멘션 자동완성

댓글에서 `@`를 입력하면 사람 목록이 열립니다. 멘션은 처음부터 알림이 됐지만, 안내는 "@아이디로 멘션할 수 있습니다"뿐이었습니다 — 남의 아이디를 외우고 있으라는 뜻입니다.

### 인쇄 페이지 번호

문서 이름과 `3 / 8`이 모든 페이지 아래에 들어갑니다.

Chromium 명령줄로는 불가능합니다. 머리글·바닥글 선택지가 Chromium 자신의 것뿐인데 거기에는 임시 파일 경로가 들어갑니다. CSS로도 안 됩니다 — 페이지 번호는 `@page` 여백 상자에 들어가는데 Chromium은 이를 구현하지 않습니다. 그래서 DevTools 프로토콜로 대화합니다. 페이지의 load 이벤트를 기다리므로 글꼴이 도착하기 전에 인쇄되는 일도 없습니다.

명령줄 방식은 폴백으로 남깁니다. 프로토콜 대화는 프로그램 실행보다 실패할 여지가 많고, **작동을 멈춘 내보내기는 페이지 번호 없는 내보내기보다 나쁩니다.**

## 성능

### 한국어 검색

측정 결과입니다. 문서 2만 건에서 `회의` 검색 시 — **ILIKE로는 41건, Postgres 전문 검색으로는 0건.**

Postgres의 토크나이저는 공백으로 자르는데 한국어는 `회의`와 `회의록` 사이에 공백을 두지 않습니다. 즉 한국어 검색은 지금까지 **전부 인덱스 없는 ILIKE**가 처리하고 있었고, 그것은 매번 표 전체를 읽습니다.

트라이그램 인덱스로 그 패턴이 인덱스를 타게 됩니다. 같은 데이터에서 3글자 질의가 **11.7ms → 0.7ms**가 되고 플래너가 스스로 인덱스를 고릅니다. 2글자 질의는 이 크기에서 여전히 스캔하는데 그 크기에서는 그게 옳은 선택이고, 표가 커지면 달라집니다.

확장은 contrib이라 모든 공식 Postgres 이미지에 들어 있지만, 만드는 데는 권한이 필요합니다. **권한이 없으면 기동을 막지 않고 인덱스만 건너뜁니다** — 검색은 이전과 똑같이 동작합니다.

검색 결과 요약문도 고쳤습니다. `ts_headline`은 전문 검색이 일치시킨 단어를 강조하는데, 한국어에서는 일치가 없으니 **문서 앞부분만** 잘라 주고 있었습니다. 이제 검색어 주변을 보여줍니다.

## 보안

로그인 실패는 200밀리초 지연이 전부였습니다. 그것은 한 번에 하나를 늦출 뿐, 동시에 보낸 백 개는 늦추지 못합니다 — 지연이 병렬로 소화되기 때문입니다.

이제 실패 횟수를 셉니다. **주소와 계정을 묶어서** 세는데, 이건 의도한 것입니다. 계정만 세면 누구나 남의 아이디를 찍어서 그 사람을 잠글 수 있고, 주소만 세면 한 사람의 실수로 같은 게이트웨이 뒤의 사무실 전체가 막힙니다. 로그인에 성공하면 횟수는 지워집니다.

## 문서

### 운영 안내

`docs/OPERATIONS.md`가 새로 생겼습니다. 백업, 복구, 마스터 키 관리 절차가 어디에도 적혀 있지 않았습니다.

`ENCRYPTION_KEY`를 잃으면 봉인된 값은 **모두 복구할 수 없습니다** — AI·SMTP·OIDC 자격 증명과 모든 사용자의 개인 키. 옆에 둔 백업도 도움이 되지 않습니다. 백업이 담은 것을 여는 것이 바로 그 키이기 때문입니다. 여기서 일어날 수 있는 가장 비싼 사고인데 적혀 있지 않았습니다.

### API 문서가 어긋나지 않도록

muni는 라우트 112개를 서비스하면서 그중 45개만 기술한 문서를 공개하고 있었습니다. 연동을 만들려는 사람은 3분의 1만 맞는 지도를 읽고 있었던 셈입니다.

이제 라우트를 등록하면서 기록하고, **테스트가 양방향으로 대조**합니다. 기술되지 않은 라우트도 실패하고, 서비스하지 않는데 기술된 것도 실패합니다. 실제로 빠져 있던 44개를 채웠습니다.

## 그 밖에

- **저장 용량** — 운영 현황이 데이터베이스와 첨부 크기를 보여주고, 첨부가 몇 기가바이트를 넘으면 알립니다. 첨부는 데이터베이스 안에 있어 백업이 그만큼 커집니다.
- **모바일** — 도구 모음이 메뉴 버튼 뒤에 숨어 있어 서식 하나 적용에 두 번 눌러야 했습니다. 이제 항상 보이고, 자리가 모자라는 항목은 따로 메뉴가 있습니다. 떠 있는 패널들이 화면보다 넓게 열리던 것도 고쳤습니다.

## 업그레이드

데이터베이스 마이그레이션이 셋 추가됩니다.

| 파일 | 내용 |
| --- | --- |
| `008_approval_line.sql` | 결재선 단계 표. 기존 승인 방식은 그대로 |
| `009_search_trigram.sql` | 트라이그램 확장과 인덱스. **권한이 없으면 건너뜁니다** |
| `010_search_snippet.sql` | 검색 요약문 함수 |

서버가 시작할 때 자동으로 적용되며 기존 데이터를 바꾸지 않습니다.

```bash
gzip -dc muni-v0.10.0.tar.gz | docker load
docker compose -f compose.example.yaml --env-file .env up -d
```

`009`가 만드는 인덱스는 문서 본문 전체를 담으므로 데이터베이스가 다소 커집니다. 문서가 많은 설치에서는 첫 기동 시 인덱스 생성에 시간이 걸릴 수 있습니다.

## 오프라인 설치

릴리스 asset에는 `muni:v0.10.0` Docker 이미지가 포함되어 있습니다.

```bash
gzip -dc muni-v0.10.0.tar.gz | docker load
docker image inspect muni:v0.10.0

cp .env.example .env
# .env의 네 값을 운영 환경에 맞게 변경합니다.
docker compose -f compose.example.yaml --env-file .env up -d
```

애플리케이션이 반드시 필요로 하는 런타임 환경변수는 다음 네 개입니다.

| 환경변수                   | 설명                                 |
| -------------------------- | ------------------------------------ |
| `POSTGRES_DSN`             | PostgreSQL 접속 문자열               |
| `BOOTSTRAP_ADMIN`          | 최초 관리자 아이디 또는 이메일       |
| `BOOTSTRAP_ADMIN_PASSWORD` | 최초 관리자 비밀번호(12자 이상)      |
| `ENCRYPTION_KEY`           | base64로 인코딩한 32-byte master key |

PDF 변환 동작만 조정하는 선택 환경변수가 두 개 있습니다.

| 환경변수               | 기본값    | 설명                                       |
| ---------------------- | --------- | ------------------------------------------ |
| `MUNI_CHROMIUM_PATH`   | 자동 탐색 | PDF Export에 사용할 headless 브라우저 경로 |
| `MUNI_PDF_CONCURRENCY` | `2`       | 동시에 실행할 Chromium 프로세스 수(1~32)   |

## 운영 정보

- 서비스 포트: `8080`
- Liveness: `/healthz`
- Readiness: `/readyz`
- REST API: `/api/v1`
- OpenAPI: `/api/openapi.yaml` — 이제 실제 라우트와 일치합니다
- MCP: `/mcp`
- 지원 DB: PostgreSQL 15 이상
- 이미지에는 PDF Export용 Chromium과 Noto CJK 글꼴이 포함되어 있습니다.
